对于固件开发人员

将您的固件添加到 Updater CE。

Updater CE 是自定义固件的社区目录和安装程序。从基础 ROM 开发您的项目，将其发布为具有正确发布资产的公共存储库，将模型条目添加到 slidia_manifest.xml，测试模型过滤器，并打开拉取请求。一个存储库可以为其支持的每种模型提供服务。

从基础开始 ROM

基础 ROM 为定制固件开发人员提供了一个干净的 Android 基础，并启用了无线射频芯片。在 Y1 上，它们支持 Wi-Fi 和 GPS 以及工厂蓝牙和 FM；在 Y2 上，它们支持 Wi-Fi、GPS 和 FM 以及工厂蓝牙。

使用这些发布资产名称

文件名是兼容性信号的一部分。保持名称准确，并将 ZIP 文件放入项目的发布资产中，而不仅仅是存储库源树中。

连接如何运作

更新程序 CE 读取清单作为其目录。每个 <package> 该行告诉它项目名称、存储库、模型和处理程序。当用户选择该项目时，更新程序会检查存储库的已发布版本并查找 rom*.zip 资产。

更新程序CE安装

使用选定的型号来选择匹配的封装和特定于型号的闪存路径。用户不必猜测文件名。

发布项目只需五步

  1. 分叉 Updater CE 存储库。 创建您自己的分叉 y1-community/Innioasis-Updater，然后在本地克隆您的分叉。
  2. 准备公共固件存储库。 确保存储库是公共的并且其版本包含正确的 ZIP 资产。你可以把 rom.zip, rom_type_b.zip, 和 rom_y2.zip 当它们属于同一版本时在同一版本上。
  3. 编辑清单。 打开 slidia_manifest.xml 在 Updater CE 分支的根目录中。为该版本支持的每个模型添加一行（Y1 和 Y2 是公共对）。这 repo 值是存储库的 owner/repository; url 是公共项目页面。
  4. 测试目录。 从编辑后的结账中运行更新程序。选择 Y1 并确认项目显示 Y1 资产。选择 Y2 并确认其显示 Y2 版本。当Type A和Type B都发布时，分别检查。
  5. 打开拉取请求。 将清单更改推送到您的分支，并针对上游 Updater CE 存储库打开拉取请求。包括项目链接、支持的型号、发布标签、资产名称和您测试的设备。

清单读取的每个属性

      
这些是当前 Updater CE 版本理解的属性。生成器仅写入您填写的内容；该应用程序对于其余部分将回退到合理的默认值。

      

        

          slidia_manifest.xml包属性及其含义
          
            
属性需要它的作用

          
          
            
name是的软件名称显示在目录和安装卡上。

            
repo是的owner/repo。该应用程序读取该存储库的 GitHub 版本。

            
device是的目标型号，大写（Y1, Y2, G1, Q3e，……）。每个模型保留一个条目。

            
url受到推崇的从目录中打开的项目页面或发行说明。

            
type, handler实践中是的type="img" 和 handler="Custom Firmware"。其他类型和非固件处理程序将被跳过。

            
brand可选目录品牌（Innioasis, Timmkoo）。空使用模型的默认品牌。

            
package_name可选发布资产文件名。默认为 rom.zip 在 Y1 上和 rom_<model>.zip 在其他型号上。

            
asset_pattern可选对于固件 zip 未命名的版本，不区分大小写的 glob rom*.zip （例如 my-firmware-*.zip).

            
type_a_asset, type_b_asset可选当文件名不包含常用标记时，识别 Y1 Type A 和 Type B zip 的 Glob。

            
icon可选徽标网址。自己发布后使用 updater.png / updater.jpg，并作为每个版本的后备。

            
icon_dark可选深色主题标志。 image_dark 是一个可接受的别名。

            
image可选二次光艺术作品，尝试后 icon.

            
post_install, post_install2可选成功安装后打开的页面。第二个包含多步骤指南。

            
portable_zips可选逗号分隔 *-mirror 发布可立即运行的可移植包的存储库。

            
derivative可选构建固件的存储库。具有相同衍生根的固件可以保留用户数据。

            
info_repo可选应用程序存储库，其版本描述了固件的部署内容。需要 post_install 或 post_install2.

            
apk_repo可选应用程序存储库，其 APK 应用程序在固件之后安装。

            
min_version可选当 Updater CE 早于此版本时隐藏该条目。

            
do_not_keep_data可选true （还 1 / yes）阻止此固件完全保留数据。

            
slug可选链接和保存的安装记录的稳定标识符。空时根据名称和型号生成。

            
description可选简短的目录描述。它可以是属性值或元素的文本。

一个版本，三项资产

          
共享版本可以包含 rom.zip, rom_type_b.zip, 和 rom_y2.zip。更新程序将它们分开分类，并从模型和硬件过滤器中进行选择。

        

        

          
不要捆绑猜测

          
请勿在 Y2 文件名下包含 Y1 包，或添加未经测试的分散、预加载器或分区数据只是为了使资产出现。

        

      

    




      
为什么模型条目在闪烁期间很重要

      
清单不仅仅是一个下载菜单。提取后，Updater CE 使用解析的模型来准备匹配的安装路径。 Y1 和 Y2 具有不同的平台文件、预加载器、分散配置和设备布局。

      
    
        
  • Y1: 更新程序准备 Y1 路径，并在使用 MTKClient 时使用设备的命名分区。
    • 
        
  • Y2: 更新程序准备 Y2 路径并使用 Y2 MT6582 配置。完全恢复可以使用来自模型正确的分散数据的物理地址。
    • 
        
  • 跨平台支持： Updater CE 可以直接跨 Windows、Linux 和 macOS（支持 Intel 和 Apple Silicon Mac）处理本机刷新，无需额外的刷新工具。
    • 
      

      
贡献者应提供正确的固件文件，而不是闪存偏移量。 不要编辑分散地址、预加载器、DA 文件或分区命令来解决损坏的包。修复发布资产并在预期模型上进行测试。
