對於韌體開發人員

將您的韌體新增至 Updater CE。

Updater CE 是自訂韌體的社群目錄和安裝程式。從基礎 ROM 開發您的項目，將其發佈為具有正確發布資產的公共儲存庫，將模型條目新增至 slidia_manifest.xml，測試模型過濾器，並開啟拉取請求。一個儲存庫可以為其支援的每種模型提供服務。

從基礎開始 ROM

基礎 ROM 為定制韌體開發人員提供了一個乾淨的 Android 基礎，並啟用了無線射頻晶片。在 Y1 上，它們支援 Wi-Fi 和 GPS 以及工廠藍牙和 FM；在 Y2 上，它們支援 Wi-Fi、GPS 和 FM 以及工廠藍牙。

用於自訂韌體開發的基礎 ROM 下載，其中每一項都支援 Android 版本和無線功能

這些圖像是啟用了設備無線無線電的庫存 Android 基礎 (AOSP)，因此自訂韌體可以添加網路功能，而不是替換無線電堆疊。它們是以下發布步驟的實際起點。

檔案名稱是相容性訊號的一部分。保持名稱準確，並將 ZIP 檔案放入專案的發布資產中，而不僅僅是儲存庫來源樹中。

連結如何運作

更新程式 CE 讀取清單作為其目錄。每個 <package> 該行告訴它項目名稱、儲存庫、模型和處理程序。當使用者選擇該項目時，更新程式會檢查儲存庫的已發布版本並查找 rom*.zip 資產。

顯現

命名項目並將其映射到模型。 Y1 和 Y2 需要單獨的行，即使它們共用儲存庫。

已發布版本

包含可安裝的 ZIP 資產。單一版本可能包含 Y1 Type A、Y1 Type B 和 Y2 套件。

更新程式CE安裝

使用選定的型號來選擇相符的封裝和特定於型號的快閃記憶體路徑。用户不必猜测文件名。

發布項目只需五步

  1. 分叉 Updater CE 儲存庫。 創建您自己的分叉 y1-community/Innioasis-Updater，然後在本地克隆您的分叉。
  2. 準備公共韌體儲存庫。 確保儲存庫是公共的並且其版本包含正確的 ZIP 資產。你可以把 rom.zip, rom_type_b.zip, 和 rom_y2.zip 當它們屬於同一版本時在同一版本上。
  3. 編輯清單。 打開 slidia_manifest.xml 在 Updater CE 分支的根目錄中。為該版本支援的每個模型新增一行（Y1 和 Y2 是公共對）。這 repo 值是儲存庫的 owner/repository; url 是公共項目頁面。
  4. 測試目錄。 从编辑后的结账中运行更新程序。選擇 Y1 並確認項目顯示 Y1 資產。选择 Y2 并确认其显示 Y2 版本。当Type A和Type B都发布时，分别检查。
  5. 打開拉取請求。 將清單變更推送到您的分支，並針對上游 Updater CE 儲存庫開啟拉取請求。包括項目連結、支援的型號、發布標籤、資產名稱和您測試的設備。

清單讀取的每個屬性

      
這些是目前 Updater CE 版本所理解的屬性。生成器僅寫入您填寫的內容；該應用程式將在其餘部分回退到合理的預設值。

      

        

          slidia_manifest.xml包屬性及其意義
          
            
屬性需要它的作用

          
          
            
name是的軟體名稱顯示在目錄和安裝卡上。

            
repo是的owner/repo。該應用程式讀取該儲存庫的 GitHub 版本。

            
device是的目標型號，大寫（Y1, Y2, G1, Q3e，……）。每個模型保留一個條目。

            
url受到推崇的從目錄中開啟的項目頁面或發行說明。

            
type, handler實踐中是的type="img" 和 handler="Custom Firmware"。其他類型和非韌體處理程序將被跳過。

            
brand可選目錄品牌（Innioasis, Timmkoo）。空使用模型的預設品牌。

            
package_name可選发布资产文件名。預設為 rom.zip 在 Y1 上和 rom_<model>.zip 在其他型號上。

            
asset_pattern可選對於韌體 zip 未命名的版本，不區分大小寫的 glob rom*.zip （例如 my-firmware-*.zip).

            
type_a_asset, type_b_asset可選當檔案名稱不包含常用標記時，識別 Y1 Type A 和 Type B zip 的 Glob。

            
icon可選徽標網址。自己發布後使用 updater.png / updater.jpg，並作為每個版本的後備。

            
icon_dark可選深色主題標誌。 image_dark 是一個可接受的別名。

            
image可選二次光藝術作品，嘗試後 icon.

            
post_install, post_install2可選成功安裝後開啟的頁面。第二個包含多步驟指南。

            
portable_zips可選逗號分隔 *-mirror 發布可立即運行的可移植套件的儲存庫。

            
derivative可選建置韌體的儲存庫。具有相同衍生根的韌體可以保留用戶資料。

            
info_repo可選應用程式儲存庫，其版本描述了韌體的部署內容。需要 post_install 或 post_install2.

            
apk_repo可選應用程式儲存庫，其 APK 應用程式在韌體之後安裝。

            
min_version可選當 Updater CE 早於此版本時隱藏該條目。

            
do_not_keep_data可選true (也 1 / yes）阻止此韌體完全保留資料。

            
slug可選連結和保存的安裝記錄的穩定標識符。空時根據名稱和型號產生。

            
description可選簡短的目錄描述。它可以是屬性值或元素的文字。

一個版本，三項資產

          
共享版本可以包含 rom.zip, rom_type_b.zip, 和 rom_y2.zip。更新程式將它們分開分類，並從模型和硬體過濾器中進行選擇。

        

        

          
不要捆綁猜測

          
請勿在 Y2 檔案名稱下包含 Y1 包，或新增未經測試的分散、預先載入器或分割資料只是為了使資產出現。

        

      

    




      
為什麼模型條目在閃爍期間很重要

      
清單不僅僅是一個下載選單。提取後，Updater CE 使用解析的模型來準備匹配的安裝路徑。 Y1 和 Y2 具有不同的平台檔案、預先載入器、分散式配置和裝置佈局。

      
    
        
  • Y1: 更新程式準備 Y1 路徑，並在使用 MTKClient 時使用裝置的命名分割區。
    • 
        
  • Y2: 更新程式準備 Y2 路徑並使用 Y2 MT6582 配置。完全恢復可以使用來自模型正確的分散資料的實體位址。
    • 
        
  • 跨平台支援： Updater CE 可以直接跨 Windows、Linux 和 macOS（支援 Intel 和 Apple Silicon Mac）處理本機刷新，無需額外的刷新工具。
    • 
      

      
貢獻者應提供正確的韌體文件，而不是快閃記憶體偏移量。 不要編輯分散位址、預先載入器、DA 檔案或分區命令來解決損壞的套件。修復發布資產並在預期模型上進行測試。
