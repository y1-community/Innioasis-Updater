Findings that motivated it (live, 06 image, 2026-10-10)

  • MTP reported 808 MB / 511 MB: Internal Storage was a folder on the 800 MiB Y2DATA; the SD filesystem was a 512 MiB root-image copy on a 121 GiB partition (also carrying the root's Y2ROOT label and a UUID in the root's family).
  • eMMC is 7423 MiB; p8 (5596 MiB, stock FAT, serial 3F93-07E6, 541 files/31 MB, stale dirty bit) was unused and write-blocked by the guard. File-level backup retained.
  • MTP throughput (libusb direct, 06): upload 8.4-11 MB/s, download about 37.7 MB/s on both volumes, hashes verified.

Changes

  1. eMMC write guard: one added span (3742720 to the exposed disk end). Tests pin ANDROID, USRDATA, p8 and every native sector reachable by a write; straddling spans, CACHE, boot/protected areas, the disk-end sector and the hidden tail stay refused. Owner-approved in chat 2026-10-10; audit entry in docs/planning/roadmap-gap-audit.md.
  2. Y2Media (tools/platform/y2_platform/internal_media.py): exact-geometry/label/UUID mount after e2fsck -p, ready record, /media/internal, never boot-critical (S02y2-media). Explicit provision names the stock serial, refuses mounted/other filesystems, migrates /data/music with SHA-256 and removes originals only after full verification (symlinks/special files/oversize/target-differs abort with originals intact).
  3. Exports: MTP Internal Storage = /media/internal/music (same fixed slot); SFTP root and the verified-upload tool follow it (cross-filesystem publish by verified copy + non-replacing link); storage status has a fourth volume; health, capabilities, bench and the USB qualification harness know it; factory reset leaves Y2Media music.
  4. SD: media format/grow (CID-confirmed, only the card controller), undersized report, recycled-mount-id marker fix, resize2fs.
  5. Reborn: internal music directory chosen from the platform's Ready record (this boot, this mount) with legacy fallback; internal volume/diagnostics follow it.
