The report

User with 28 600 songs on a 512 GB card (install 03df8d42, report 9765e1e7, Beta 8.14): "Couldn't complete that" for any song from All Songs, and a first scan of "10 to 15 minutes".

FindingEvidence
Every play from All Songs refused17 × invalid queue bounds: MAX_QUEUE 20 000 < 28 600. A saved queue is ≈ 500 bytes per song in a session capped at 8 MiB, so more than ≈ 16 700 songs never saved either
Scan timeFull scan 757.8 s (12 890 files read, 15 710 reused): database 504.7 s, FFmpeg open 190 s, probe 30.5 s, 3.6 GB read. The scan right after, nothing changed: 759.2 s, of which database 749.2 s — and that scan runs at every start
Cause of the database timeThe scan probe's INSERT … SELECT … WHERE t.id IS NOT NULL over scan_candidates ⟕ tracks is planned as SEARCH t USING INDEX (source_id=?) then SCAN c: every track of the source per 64-file batch (1.7 s per batch on the player, 447 batches)

What changed since Beta 8.15

PartChange
QueueMAX_QUEUE 5 000 (≈ 2.5 MB session). A larger collection plays as a window around the chosen song (a tenth before it); Shuffle takes a random 5 000 of the whole collection; positions are chosen before any song is copied; a saved queue over the limit is trimmed around the current song instead of rejected (Reborn 122607f)
Scan probeMatching track ids come from the indexed lookup itself and are inserted into scan_seen by id. Host benchmark at 28 600 tracks: 54.7 → 0.08 ms per 64-file batch (Reborn 5c7e768)
Tag readingNew and changed files are read on up to 3 worker threads (cores online under the LibraryScan lease, one left for UI and playback), nice 10, results applied in file order; panics stay isolated per file. Host: 3.3× faster for 600 files (Reborn 4922cab)

Expected on the reporting player (not measured yet)

A rescan with no changes: seconds of database work plus walking the folders, instead of 12.7 min. A first scan of a new 28 600-song library: the 8.4 min of database time gone, and the tag reading spread over three cores (the SD card's read speed now sets part of the pace).
