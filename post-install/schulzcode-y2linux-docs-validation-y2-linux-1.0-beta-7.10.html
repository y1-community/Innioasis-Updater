Device result of Beta 7.9 (owner's player)

The automatic Internal Storage setup passed on real hardware: on the first restart after the confirmed update the stock FAT became Y2MEDIA (label, UUID, start/size, features, 358 336 inodes, 1 432 576 blocks identical to the 2026-10-10 original), 509 old files kept in Old Player Files hash-identical to the backup, the 3 leftovers dropped, setup ≈16 s at start, record and temporary copies removed; on the update's health boot it waited (update_in_progress). Deleting Old Player Files over MTP then hung the player: kernel oops (pstore) in dma_cache_maint_page from musb_gadget_queue, offset 0x10 / length 0 (evidence 20261017/usb-zlp-oops).

Since Beta 7.9

PartChange
USB crashuMTP ends every transfer that ends on a packet boundary with a zero-length packet; FunctionFS gave it kmalloc(0) = ZERO_SIZE_PTR and musb DMA-mapped that address (6.18 dma_map_phys → cache maintenance of a non-existent page). musb now never maps a zero-length request (it is sent by PIO, as before). Any packet-aligned copy, listing or delete could trigger it. (Linux da0917d)
Move and copy on the playerMoveObject and CopyObject, announced in DeviceInfo (Windows Explorer and libmtp hosts use them). Same storage: rename, handle kept. Between Internal Storage and the SD card and for copies: each file copied like an upload (space reserve, hidden temporary name, fsync, never replacing a name, time kept), the source of a move removed only after the complete copy. Refused: into itself, over a name, into read-only storage, moving out of Old Storage; copying out of Old Storage works. (Linux 4c0a54d)
Host tooltools/usb/mtp-file-ops.c (libmtp): packet-boundary sizes 0 B–40 MB read back, 600 files, rename, move, copy, folder to the SD card and back, single and folder deletes, liveness after each step.

Host evidence: 793 Y2Linux host tests (real responder protocol tests for MoveObject/CopyObject, mutation-checked), 514 Reborn tests. Device run of mtp-file-ops owed after the OTA install.

Known gaps

A very large CopyObject or a move of a large folder between storages runs inside one MTP operation; a host may time out while the player keeps copying (the result is complete or nothing). Windows Explorer has not been run against the player in this session.
