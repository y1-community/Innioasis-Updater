What changed since Beta 8.25

The twelve uploaded reports pending on 2026-10-23 (8.16–8.25, ten players) were reviewed against Beta 8.25; findings F35–F41 in the review ledger (UserReports/REVIEWED.md), with new evidence for F12 and F13. No Reborn code changed.

FindingChangeEvidence
F36: after a real drain to 5 % a player turned off 15–22 s after every start, also on a charger at 3.72–4.03 V, five times in 13 h (97f11bb1, 8.16)Three parts. A start on a charger no longer restores a saved percentage lower than the live estimate (a charger only adds charge; the charging screen can run for an hour first). The PMIC's power-on OCV is used only when the first sample comes within 2 min of the kernel start (after the charging screen it predates the charge). The 5 % shutdown applies on battery only: on a charger the shown value cannot fall, and the 3.4 V floor still turns a player off whose charger cannot carry the load. With the report's values the starts now show 80 % and 39 % and stay up; on battery a saved 5 % at 3.63 V still shuts downLinux 1e51811; tests/test_battery_soc.py
F37: turning Wi-Fi on after the player slept with Wi-Fi off showed STARTING, then OFF or "interface disabled" 3 s later, a scan was refused, a second tap worked (72f7e3ee, a19646dd, 3 times)Every sleep switched Wi-Fi off with rfkill block wlan, which also sets the default for every Wi-Fi rfkill made later; the wake restored it only when Wi-Fi was on. Reborn switches Wi-Fi on per device, so the cfg80211 rfkill made when the card starts came up blocked. y2-radio now switches each Wi-Fi rfkill by itself and never changes the defaultLinux 7698bb1; tests/test_suspend_policy.py

F38: on a nonstandard charger (dumb adapter, charge-only cable) the player stayed awake and drained while "Charging" (cb904ffb, e7604e73)Such sources get 450 mA, what a PC port already gets here, instead of 70 mA (below the awake load; stock asks 1100 mA).
