Reborn settings map

> **Source-contract scope.** Where every setting lives (since 1.0 Beta 9.2.10) and the rules for adding > one. Code: `crates/reborn-ui/src/pages.rs` (`settings`, `system_menu`, `library`, Sound, Display), > `crates/reborn-ui/src/customize.rs` (Customize's pages, pickers and hints).

Before you add a setting

First find the right place, then add the setting. A new setting never goes "somewhere for now". Ask:

  1. Is it needed at all? Prefer a good default to a setting (the project keeps Reborn free of feature

    creep; requests that only some people want belong to plugins later).

  2. Which question does it answer? Pick the place below whose question it answers. If two seem to fit,

    take the one a listener would open first when looking for it.

  3. Does the page still fit one screen? At most six rows on a page (the root holds eight). If a page

    would get a seventh, group related rows into a sub-page of their own with a name that says what is inside, rather than letting the page scroll.

  4. Name it by what it does, show its value. The row's label says what changes ("Buttons While Screen

    Off", not "When Screen Off"); its value on the right says what it is now ("Play Buttons", not "On").

  5. Use the matching control. On/off: a switch. Two named choices: Select steps them, the value shows

    which. Three or more: a picker page with a check mark on the current choice. A level or a time: a picker or a card with a slider.

  6. Give it a hint. Customize's settings carry one line at the bottom saying what the setting in focus

    does (customize::hint); pickers say what each choice means.

  7. Update this map and the previews (app/reborn/src/bin/reborn-preview.rs) in the same change.

A session is saved with its screen: a new page is a sub-page (an existing screen plus a navigation filter, as Screen::Customize with "browsing") unless older versions can read a new Screen value, so that Restore Previous System does not throw the session away.

The Quick Menu (hold Power)

Since 1.0 Beta 9.3.15 (Y2Linux #85), holding Power on any screen opens the Quick Menu; releasing keeps it open, Back or a short press of Power closes it. It holds what people change on the go, without walking into Settings, and nothing else:

┌ Quick Menu ─────────────────────────── Battery 72 % ┐   a centred panel; it grows in over the
│ [ Wi-Fi        network ] [ Bluetooth     device ] │   dimmed screen, the tiles one after another
│ [ ☀ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━○──────  60 % ] │
│ [ ☾ Sleep Timer ]  [ ↻ Restart ]  [ ⏻ Power Off ] │
└────────────────────────────────────────────────────┘

The wheel goes Wi-Fi → Bluetooth → Brightness → Sleep Timer → Restart → Power Off; the menu opens on Brightness. Wi-Fi and Bluetooth: Select switches them, the tile fills with the accent while on. Brightness: Select, turn the wheel, Select (the Display card's adjustment). Sleep Timer opens the timer's picker. Restart and Power Off act at once and wait while the platform works (an update). Keep holding Power with the menu open: after 3 s a ring fills around the Power Off tile ("Hold to Turn Off") and turns the player off 1.2 s later, as a hold always did; the hardware resets the player after 10 s. Over the keyboard, a pairing question or a message the full-screen ring starts at once. Skins get the same panel in their palette. Each control is also where it always was in Settings; anything added here must be a quick control that already has its place in the tree (six tiles fill the panel). Code: crates/reborn-ui/src/quick_menu.rs (rows, actions), views_quick.rs (the panel).
