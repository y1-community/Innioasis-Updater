Since Beta 7.10

PartChange
Faster copies to the playerMulti-packet (mode 1) receive DMA for USB bulk OUT: one DMA program per request (64 KB for MTP) instead of a CPU read of every 512-byte packet. At the transfer's short or zero-length packet the CPU waits until two samples agree (RXCOUNT counts down while the engine unloads a packet), stops the channel and reads only that packet. On by default (rx_dma=2); echo 0 > /sys/devices/platform/11200000.usb/rx_dma returns to PIO, never to mode 0. The stock MediaTek kernel (REA) used mode 1 only for mass storage. (Linux 1f86b4f, b49afaa, 049df5c, 10ec3eb)
Test tooltools/usb/mtpbench.c reads the closing zero-length packet of a download that fills its last read. (64af1b2)
