What changed since Beta 8.37

ChangeDetailEvidence
Bluetooth: sound after Pause → Play (ledger F43, install fae53a8f, AirPods Pro 2)On Bluetooth, Pause releases the output and Play opens a new stream where the song was (about half a second). A BlueALSA stream drained and prepared again stayed silent in the headphones after every in-place resume (reports fef6e1e6 on 8.29, 73547e56 on 8.36), while every new stream — a skip, or a close and reopen 0.4 s apart — played. Wired pauses still hold in placereport timelines; not yet confirmed by ear with headphones that showed it
A smooth wave that moves with the musicThe playing wave is one ribbon with shared joints and a one-pixel fading edge (anti-aliased without MSAA, no beading). Its height follows the loudness (typical music as before, loud up to about a third more, quiet calmer), bass swells it, highs ripple it. Measured in the audio thread before the volume (three bands, one-pole filters, meter.rs), timed by the output's delay (Bluetooth too). Home's now-playing card shows the same wavemeter tests (bands, loudness, delay, staleness); previews 14e/14f; on device smooth edges, ripple following the music, ≈1.7 ms CPU a frame

No kernel, platform, memory map, partition or packaging change; session and settings unchanged.
