Sources

What changed since Beta 8.16

#51: headphones silent after pause, lock and Next; ALSA -110 on every Play until a reboot#51 report (install 2813306c, the #48 player, 8.16): 12 failed opens, both crystal tries XTAL_READY -110 each time, also after runtime rail cyclesStock starts the CS43131 crystal with the codec and never stops it between streams (REA on the stock kernel); the upstream driver stopped it at every hw_free and restarted it at the next hw_params. Now a started crystal runs until the codec runtime-suspends; a start forces its writes to the chip, clears a stale ready flag, logs the live clock state when it fails, and cycles the codec rails once before an open fails. y2_hp/xtal counts failures and recoveries (kernel overlay 0030)

Known gaps

  • Not run on a player before publishing. Owed on the owner's player: #51 (pause 3 min, lock, Next, 50 quick Nexts,

    y2_hp/xtal), codec rails idle after stop, sleep drain with the crystal running while the codec is active, a Connect while auto-reconnect pages, SBC steps at range, the F17/F18 paths (rare).

  • The rail cycle and the DSI double read are untested on hardware; both only run on an already failing path.
  • HLS radio (BBC) and an on-device SD repair: later betas (owner decision 2026-10-21).
  • Unchanged: #42, #45, #47 confirmation, WAF rule and billing alert, USB DAC check, video not for 1.0.
