What changed since Beta 8.13

Request / reportCauseChange
"Every shuffle is the same order"The shuffle seed was the start song's ID plus its index (main.rs play_members), and Shuffle rows always started on the first song: identical order every timeSeed from getrandom per shuffle (reborn_platform::random_u64), splitmix64 with a 64-bit range reduction; a Shuffle row lets any song start; a song picked with Shuffle on still plays first. Reborn 2861ec9, tests shuffle_and_seek_tests
"Seeking jumps ~30 s per tick"A held Previous/Next sent Seek(±30 000) every 90 ms (≈ 5.5 min of song per second)The UI sends the direction; the step is 1 s for the first 1.5 s held, then 3 s, then 10 s, at most 1/60 of the song (Reborn 2861ec9)
"All Songs and Shuffle on Genres"All Songs existed since 8.8; Shuffle did notA Shuffle row under All Songs on a genre (also in Cover Flow)
"Long titles push into the menu"The Home card's now-playing title was drawn unshortened at x=356Fitted to 200 px with an ellipsis, like the line below
Report bf017f02: storage_error "I/O error, dev mmcblk0 … WRITE_ZEROES" during the Internal Storage setupThe eMMC advertised TRIM, so mke2fs's zero-out became an erase, which the MSDC guard refuses (storage-policy.h); the kernel then wrote zeros, data fineOverlay 0009: the guarded eMMC marks TRIM broken in init_card, so zero-outs write zero pages (Linux f9a3bd8)
