What changed since Beta 8.8

PartChange
Charging (#47)The start sequence refused any inherited charge voltage other than 4.175/4.2 V; the reporter's player held 4.1875 V (selector 31, probably left by stock firmware) and never charged on any charger (fault 0x80, -EIO, nothing in check_*). Now whatever CV, input OVP and battery OVP earlier software left is replaced by the stock values (4.175 V, 7 V, 4.3 V on) and read back; only a battery over-voltage the detector reports refuses. Refused inherited values are recorded in check_*. All 32 CV, 16 input OVP and the battery OVP states tested. Linux 4dc193e, 2ebca90.
Error reports over Wi-FiOpt-in uploads (the one-time question, Settings switch, Send Report Now, install ID) to a Cloudflare Worker + private R2 bucket (180-day expiry), pulled by tools/reports/fetch.py. Only on Wi-Fi, TLS clock, no update, ≥ 15 % or charging; certificate checked, no redirects; retries up to 3 days. Receiver budget in a Durable Object: 100 reports / 40 MiB a day for all, 10 per install, 30 per network, 2 MiB each: R2 stays in its free tier. ERROR-REPORTS, receiver, plan R3/R4.
Report screensNo topic for Save Report (8.9) or Send Report Now; live progress like the update download (Collect · Clean · Send/Save, percent, KB, time left).
TriggersNo report for: Wi-Fi joining a network (the failure record is rewritten on every connection), a sleep a wake event cancelled (-EBUSY), a pulled SD card's I/O errors, the boot-time DSI read lag when the screen lit anyway.
