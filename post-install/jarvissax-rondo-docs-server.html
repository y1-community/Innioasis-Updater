Setting up a Rondo server

You don't need a server. Rondo talks to YouTube Music and YouTube itself, straight from the Y1 (Directly to YouTube, what a Rondo without a server uses), and the card, the radio, the dashboard and updates never needed one. A Rondo server is optional: a small service you run yourself, at home or on a VPS, that does the YouTube part for the Y1 instead. With it:

  • The Y1 never talks to YouTube or Google. The server browses YouTube for it and passes the

    audio and video through, so YouTube sees the server, not the Y1.

  • yt-dlp finds the streams. It keeps up with YouTube's changes and the server updates it every

    day.

  • The server has its own YouTube account, signed in on its admin page.
  • Headphone match (Settings › Sound) looks up your headphone model's correction through it.

Rondo 1.0 needed a server for YouTube; Rondo 2.0 doesn't. Nothing goes through anyone else's computer either way.

One server serves one Y1. It needs Docker with Compose, about 1 GB of disk, and has to stay on while you listen.

It runs on regular PCs and servers (x86-64) and on 64-bit ARM, such as a Raspberry Pi 4 or 5 with the 64-bit Raspberry Pi OS, or most NAS boxes. 32-bit systems don't work, because the tools it uses to reach YouTube aren't made for them. So far it has been tested on x86-64 only.

At home is simplest. Pick a VPS if you want the Y1 to use your server away from home too. (Away from a home server, you can switch the Y1 to Directly to YouTube.)

At home

Install Docker, then in a terminal:

git clone https://github.com/jarvissax/rondo.git
cd rondo
docker compose -f infra/compose.home.yaml up -d

Docker downloads the ready-made server (for regular PCs and 64-bit ARM like a Raspberry Pi 4 or 5) and starts it, with a small companion that installs its updates later. When it's running, get the one-time setup code:

docker logs rondo | grep "Rondo setup"

You'll also need this computer's address on your network (something like 192.168.1.10). Give it a fixed address in your router's settings, often called a "DHCP reservation". Otherwise it can change one day and the Y1 loses the server.

Your server's address is http://<that address>:3000. Carry on with [Finish the setup](#finish-the-setup).

On a VPS

You need:

  • a VPS with Docker; a small one is enough,
  • a domain or subdomain whose DNS A record points at the VPS (for example

    music.example.com),

  • ports 80 and 443 free on the VPS.
git clone https://github.com/jarvissax/rondo.git
cd rondo
echo "RONDO_DOMAIN=music.example.com" > infra/.env
docker compose -f infra/compose.vps.yaml up -d
docker logs rondo | grep "Rondo setup"

This starts the server and Caddy in front of it. Caddy gets a certificate from Let's Encrypt and speaks the older kind of HTTPS that Android 4.2 still understands (see the comments in infra/Caddyfile). You can check that from any computer:

openssl s_client -connect music.example.com:443 -tls1_2 -cipher ECDHE-RSA-AES128-SHA </dev/null

It should print a certificate chain and Verify return code: 0 (ok).

Two things that break the Y1's connection:

  • Cloudflare's proxy. If your DNS is on Cloudflare, set the record to "DNS only" (gray cloud).

    Cloudflare's HTTPS doesn't offer what Android 4.2 needs.

  • Another web server's defaults. If the VPS already runs Caddy or nginx on 80/443, use

    compose.home.yaml behind it instead, and give your site the tls settings from infra/Caddyfile. For nginx, allow TLS 1.2 with ECDHE-RSA-AES128-SHA and use an RSA certificate.

Your server's address is https://music.example.com.

Finish the setup

  1. Admin page: open <your server's address>/admin in a browser. Enter the setup code from

    the log and choose an admin password.

  2. Connect the Y1: on the admin page, go to Device and press Connect a Rondo. It shows

    a 6-digit code, good for 10 minutes.

  3. On the Y1, open Settings › YouTube › Connection › Connect to a server. Type your server's

    address and, on the next screen, the code from step 2. (Typing is quicker in the dashboard: open Settings › Dashboard on the Y1, the address it shows on your phone or computer, then its YouTube page.)

Settings › YouTube › Connection on the Y1 now has My server chosen and says it's connected; Connection test checks it. YouTube Music and YouTube now go through your server. To go back to YouTube directly at any time, choose Directly to YouTube there; the server stays connected for when you switch back.

The admin page

Open <your server's address>/admin any time to see how things are going. A sign-in lasts 12 hours.

  • Overview: whether everything works, from the Y1 through the server to YouTube, and what

    to do when something doesn't.

  • YouTube account: sign in with a code, add or replace cookies.txt, or sign out.
  • Device: the connected Y1, when it was last seen, and buttons to connect a different one or

    disconnect it.

  • Resolver: the yt-dlp version, Update now, and Test playback, which checks that a

    video can be found the way the Y1 would ask for it.

  • Updates: the Overview says when a newer Rondo or yt-dlp is out. The server checks every 6

    hours: Rondo's update page for Rondo, GitHub for yt-dlp. UPDATE_CHECK=0 in its environment turns that off.

  • Activity: the last 100 warnings and errors, newest first.
  • Admin account: change the password or sign out.

Your YouTube account (optional)

This is the server's own account, which a Y1 on My server uses. (Directly to YouTube, the Y1 signs in by itself: Settings › YouTube › YouTube account, or the dashboard's YouTube page.)

Without an account you can still search and play anything, open artists, albums and public playlists, and see a general home page. Rondo hides Library, Subscriptions and History until an account is connected.

Sign in with a code works like signing in a smart TV. On the admin page, go to **YouTube account and press Get a code**. Open google.com/device on your phone, enter the code and allow access. It renews itself and keeps working when you use the same account in a browser. **Sign out** on the admin page undoes it, at Google too.

cookies.txt adds YouTube Music's own home and history. YouTube only gives those to a browser session:

  1. Open a private window and sign in at youtube.com. A separate Google account for Rondo is

    the safest choice, because YouTube sometimes flags accounts used by servers.

  2. Export the cookies with a "cookies.txt" browser extension (Netscape format).
  3. Close the private window right away. If the browser keeps using that session, Google

    replaces it and the server gets signed out.

  4. On the admin page, press Upload cookies.txt. It says who's signed in when it worked, and

    Activity warns you if the cookies stop working later.

Keeping it running

  • yt-dlp updates itself every day. When YouTube changes something and playback stops, press

    Update now on the admin page's Resolver page.

  • Updating the server: when a newer Rondo is out, the admin page's Overview says so. Press

    Update: the server downloads the new version and restarts on it, in a minute or two. Your admin password, account and connected Y1 stay; sign in to the admin page again afterwards. This is the job of the rondo-updater container next to the server, which needs Docker's socket and only ever touches the rondo container. If you'd rather update by hand:

  cd rondo
  git pull
  docker compose -f infra/compose.home.yaml pull           # or compose.vps.yaml
  docker compose -f infra/compose.home.yaml up -d

A server set up before 1.0.2 built itself and has no updater yet; those four lines move it to the ready-made images, with Update from then on. Your admin password, account and connected Y1 are kept on a Docker volume and survive updates either way.

  • Updating the Y1: Rondo 2.0 checks GitHub for its own updates, server or not

    (Settings › System › Software update, see Updating Rondo). The server still hands a Rondo 1.0 its updates, and tells it when a release needs a new firmware, as 2.0 does: it fetches them from Rondo's update page and passes them on.

  • The server and Rondo share a version number. When the admin page says a newer Rondo is out,

    update the server too (above), even if only the Y1 changed; that keeps them in step.

  • One Y1 per server. Connecting another Rondo disconnects the previous one.
  • Forgot the admin password? Remove it and restart. The server prints a new setup code, and

    your Y1 stays connected:

  docker exec rondo node -e 'const f="/data/config.json",fs=require("fs"),d=JSON.parse(fs.readFileSync(f));delete d.adminHash;fs.writeFileSync(f,JSON.stringify(d,null,2))'
  docker restart rondo
  docker logs rondo | grep "Rondo setup"

Privacy

The server doesn't store audio or video; it passes streams through as they play. (A video you download is saved on the Y1's card, not on the server.) Your cookies and the code sign-in stay on the server's Docker volume, readable only by the server, and are never shown or written to the logs. With My server chosen, the Y1 reaches YouTube only through your server, never Google directly. It still checks GitHub for Rondo's own updates.

With a server, Rondo sets its time zone from it: once each time the Y1 joins Wi-Fi, the server asks ipwho.is (or, if that fails, ipapi.co) which time zone the Y1's public IP address is in. Only that address is sent; a Y1 on the same network as the server is looked up by the server's own address. Answers are kept for 12 hours. Until a zone is named, the Y1 uses UTC. Directly to YouTube, the Y1 asks the same two services itself. Either way, **Settings › System › Date & time** can set the time zone by hand instead.

How the server works, and its API, are described in docs/dev/server-api.md.
