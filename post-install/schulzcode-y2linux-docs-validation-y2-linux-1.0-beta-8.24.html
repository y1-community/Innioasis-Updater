Why 8.23 was not enough (#52)

EvidenceWhat it shows
#52 report y2linux-report-20261022-220205 (install 2813306c, 8.23, first boot after the OTA)the crystal came up in 30 ms and the player took about 4.5 min of skipping (95 kept-sink reuses), then failed at a 48 kHz start (PLL_READY -110, ALSA -110) followed by XTAL_ERR (status1=49, errors=5). In this player's 8.21, 8.22 and 8.23 sessions every failure is a 48 kHz start; 44.1 kHz starts never failed. Reporter: three to four times more skips than before, and a restart did not bring the sound back
Stock system.img /etc/audio_policy.confthe primary output (speaker, wired headset/headphone) has sampling_rates 44100 only: Android resamples 48 kHz before the HAL. With the stock kernel's set_freq (rate bits only, no PLL), stock never runs the CS43131's PLL
Y2Linux 8.17–8.2348 kHz sources played at 48 kHz through the codec PLL (fed by the crystal); the one thing stock never does is where #52's crystal falls over

What changed since Beta 8.23

AreaChangeEvidence
No codec PLL (#52)The AFE front end and I2S back end offer 44.1 kHz only (stock's only output rate), and the codec refuses any rate its 22.5792 MHz crystal does not clock (-EINVAL before any clock work, logged). Reborn's wired plan always asks for 44.1 kHz; the decoder converts 48, 96 kHz and other rates (as stock's mixer did). Every track now plays on in the one open headphone sink, whatever its rateLinux f66d71d (kernel/audio/mt6582-afe.c, overlay 0030, tools/platform/capabilities.json, tests/test_codec_clock.py); Reborn 83f0082
Self-healing (#52)A crystal error flag seen at a stream start power-cycles the codec (rails off 500 ms, then the stock power-up) before that stream, which waits for the restarted crystal. y2_hp/xtal gains cycles=Linux f66d71d (register model)
Cold start at probeA probe that finds the codec's rails on switches them off for 500 ms before powering up, and logs cold start. Correction: the commit and code comment assume a restart leaves VGP2 on; on the owner's player a software restart and an OTA restart both reset VGP2 (it comes up at its 2.5 V reset value and off), so a restart already cold-starts the DAC and this path does not trigger (cold_start=0). It stays as a safety netowner's player, two restarts
