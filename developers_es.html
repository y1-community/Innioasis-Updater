Para desarrolladores de firmware

Agregue su firmware al Updater CE.

Updater CE es el catálogo comunitario y el instalador de firmware personalizado. Desarrolle su proyecto desde una base ROM, publíquelo como un repositorio público con los activos de lanzamiento correctos, agregue las entradas del modelo a slidia_manifest.xml, pruebe los filtros del modelo y abra una solicitud de extracción. Un repositorio puede servir a todos los modelos que admite.

Empezar desde una base ROM

Las ROM base brindan a los desarrolladores de firmware personalizados una base de Android limpia con los chips de radio inalámbricos habilitados. En el Y1 habilitan Wi-Fi y GPS junto con Bluetooth y FM de fábrica; en el Y2 habilitan Wi-Fi, GPS y FM junto con el Bluetooth de fábrica.

Descargas base ROM para desarrollo de firmware personalizado, con la versión de Android y funciones inalámbricas que cada una habilita
DescargarDispositivoAndroidFunciones inalámbricas
rom.zipY1 · Type AAndroid 4.2.2Agrega Wi-Fi y GPS al Bluetooth y FM de fábrica (FM ya funciona en el Y1 de fábrica). Para Y1 reproductores que se enviaron con OS 2.0.0 o posterior.
rom_type_b.zipY1 · Type BAndroid 4.2.2Agrega Wi-Fi y GPS al Bluetooth y FM de fábrica (FM ya funciona en el Y1 de fábrica). Para Y1 reproductores que se enviaron con un sistema operativo anterior a 2.0.0.
rom_y2.zipY2Android 4.4.2Agrega Wi-Fi, GPS y FM al Bluetooth de fábrica. El chip de radio Y2 está completamente habilitado, por lo que FM también está disponible aquí.

Estas imágenes son la base estándar de Android (AOSP) con las radios inalámbricas del dispositivo habilitadas, por lo que un firmware personalizado puede agregar funciones de red en lugar de reemplazar la pila de radio. Son el punto de partida práctico para los siguientes pasos de publicación.

Utilice estos nombres de activos de lanzamiento

El nombre del archivo es parte de la señal de compatibilidad. Mantenga los nombres exactos y coloque los archivos ZIP en los activos de lanzamiento del proyecto, no solo en el árbol de fuentes del repositorio.

Nombres de activos ZIP de firmware y dispositivos compatibles
ActivoDispositivoFerreteríaSignificado

rom_type_b.zipY1Type BY1 dispositivos que se enviaron con un sistema operativo anterior a 2.0.0.

No cambie el nombre de un paquete para que se ajuste a otro modelo. Y1 y Y2 usan diferentes archivos de plataforma MediaTek y configuración de actualización. Publique el paquete para el hardware que realmente admite.

Cómo funciona la conexión

Updater CE lee el manifiesto como su catálogo. Cada <package> La línea le dice el nombre del proyecto, el repositorio, el modelo y el controlador. Cuando un usuario elige ese proyecto, Updater verifica las versiones publicadas del repositorio y busca una rom*.zip activo.

Manifiesto

Nombra el proyecto y lo asigna a un modelo. Y1 y Y2 necesitan líneas separadas, incluso cuando comparten un repositorio.

Lanzamiento publicado

Contiene los recursos ZIP instalables. Una única versión puede contener los paquetes Y1 Type A, Y1 Type B y Y2 juntos.

Instalación del actualizador CE

Utiliza el modelo seleccionado para elegir el paquete correspondiente y la ruta de flasheo específica del modelo. El usuario no debería tener que adivinar el nombre de un archivo.

Publicar un proyecto en cinco pasos

  1. Bifurque el repositorio de Updater CE. Crea tu propio tenedor de y1-community/Innioasis-Updater, luego clona tu bifurcación localmente.
  2. Prepare un repositorio de firmware público. Asegúrese de que el repositorio sea público y que su versión contenga los recursos ZIP correctos. puedes poner rom.zip, rom_type_b.zip, y rom_y2.zip en la misma versión cuando pertenecen a la misma versión.
  3. Edite el manifiesto. Abierto slidia_manifest.xml en la raíz de su bifurcación Updater CE. Agregue una línea para cada modelo que admita la versión (Y1 y Y2 son ​​el par común). El repo El valor es el del repositorio. owner/repository; url es la página pública del proyecto.
  4. Prueba el catálogo. Ejecute Updater desde la caja editada. Seleccione Y1 y confirme que el proyecto muestra los activos Y1. Seleccione Y2 y confirme que muestra la versión Y2. Marque Type A y Type B por separado cuando ambos estén publicados.
  5. Abra una solicitud de extracción. Envíe el cambio de manifiesto a su bifurcación y abra una solicitud de extracción en el repositorio ascendente de Updater CE. Incluya el enlace del proyecto, los modelos compatibles, la etiqueta de lanzamiento, los nombres de los activos y los dispositivos que probó.

Una versión, tres activos

          
Una versión compartida puede contener rom.zip, rom_type_b.zip, y rom_y2.zip. Updater los clasifica por separado y elige entre los filtros de modelo y hardware.

        

        

          
No hagas conjeturas

          
No incluya un paquete Y1 bajo el nombre de archivo Y2, ni agregue datos de dispersión, precargador o partición no probados solo para que aparezca un activo.

        

      

    




      
Por qué son importantes las entradas del modelo durante el flasheo

      
El manifiesto no es sólo un menú de descarga. Después de la extracción, Updater CE utiliza el modelo resuelto para preparar la ruta de instalación correspondiente. Y1 y Y2 tienen diferentes archivos de plataforma, precargadores, configuración de dispersión y diseños de dispositivos.

      
    
        
  • Y1: el actualizador prepara la ruta Y1 y usa las particiones con nombre del dispositivo cuando se usa MTKClient.
    • 
        
  • Y2: el actualizador prepara la ruta Y2 y utiliza la configuración Y2 MT6582. La recuperación completa puede utilizar direcciones físicas de los datos dispersos correctos del modelo.
    • 
        
  • Soporte multiplataforma: Updater CE maneja la actualización nativa directamente en Windows, Linux y macOS (compatible con Intel y Apple Silicon Macs) sin herramientas de actualización adicionales.
    • 
      

      
Los contribuyentes deben proporcionar archivos de firmware correctos, no compensaciones de flash. No edite direcciones dispersas, precargadores, archivos DA ni comandos de partición para solucionar un paquete defectuoso. Corrija el recurso de lanzamiento y pruébelo en el modelo previsto.
