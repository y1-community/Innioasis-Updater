# הוסף את הקושחה שלך ל-Updater CE.

Updater CE הוא קטלוג הקהילה ומתקין עבור קושחה מותאמת אישית. פתח את הפרויקט שלך מבסיס ROM, פרסם אותו כמאגר ציבורי עם נכסי השחרור הנכונים, הוסף את ערכי המודל ל- `slidia_manifest.xml`, בדוק את מסנני הדגם ופתח בקשת משיכה. מאגר אחד יכול לשרת כל דגם שהוא תומך בו.[צפה במקור Updater CE](https://github.com/y1-community/Innioasis-Updater)[עיין בהורדות תוכנה](firmware_he.html)

## התחל מבסיס ROM

רכיבי ROM בסיסיים מעניקים למפתחי קושחה מותאמים אישית בסיס אנדרואיד נקי עם שבבי הרדיו האלחוטיים מופעלים. ב-Y1 הם מאפשרים Wi-Fi ו-GPS לצד Bluetooth ו-FM של היצרן; ב-Y2 הם מאפשרים Wi-Fi, GPS ו-FM לצד Bluetooth של היצרן.הורדות בסיס ROM לפיתוח קושחה מותאם אישית, עם גרסת אנדרואיד ותכונות אלחוטיות שכל אחת מהן מאפשרת[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom.zip)[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom_type_b.zip)[``](https://github.com/y1-community/y2-ata-rom/releases/download/y2-ata/rom_y2.zip)

| הורדה | מכשיר | Android | תכונות אלחוטיות |
| --- | --- | --- | --- |
| rom.zip | Y1 · Type A | Android 4.2.2 | מוסיף Wi-Fi ו-GPS למפעל Bluetooth ו-FM (FM כבר עובד על Y1 מהמפעל). עבור Y1 נגנים שנשלחו עם מערכת הפעלה 2.0.0 ואילך. |
| rom_type_b.zip | Y1 · Type B | Android 4.2.2 | מוסיף Wi-Fi ו-GPS למפעל Bluetooth ו-FM (FM כבר עובד על Y1 מהמפעל). עבור Y1 שחקנים שנשלחו עם מערכת הפעלה קודמת מ-2.0.0. |

תמונות אלה הן בסיס אנדרואיד (AOSP) המניות עם מכשירי הרדיו האלחוטיים מופעלים, כך שקושחה מותאמת אישית יכולה להוסיף תכונות רשת במקום להחליף את מחסנית הרדיו. הם נקודת ההתחלה המעשית לשלבי הפרסום שלהלן.

## איך החיבור עובד

Updater CE קורא את המניפסט כקטלוג שלו. כל אחד `<package>` line אומר לו את שם הפרויקט, המאגר, המודל והמטפל. כאשר משתמש בוחר בפרוייקט זה, Updater בודק את המהדורות שפורסמו של המאגר ומחפש א `rom*.zip` נכס.

### מניפסט

נותן שם לפרויקט וממפה אותו למודל. Y1 ו-Y2 צריכים שורות נפרדות, גם כאשר הם חולקים מאגר.

### מהדורה שפורסמה

מכיל את נכסי ה-ZIP הניתנים להתקנה. מהדורה בודדת עשויה להכיל את החבילות Y1 Type A, Y1 Type B, ו-Y2 יחד.

### התקנת Updater CE

משתמש בדגם שנבחר כדי לבחור את החבילה התואמת ואת נתיב ההבהוב הספציפי לדגם. המשתמש לא צריך לנחש שם קובץ.

## פרסם פרויקט בחמישה שלבים
  - מזלג את מאגר Updater CE. צור מזלג משלך [y1-community/Innioasis-Updater](https://github.com/y1-community/Innioasis-Updater), ואז לשבט את המזלג שלך באופן מקומי.
  - הכן מאגר קושחה ציבורי. ודא שהמאגר הוא ציבורי והשחרור שלו מכיל את נכסי ה-ZIP הנכונים. אתה יכול לשים `rom.zip`, `rom_type_b.zip`, ו `rom_y2.zip` באותה גרסה כשהם שייכים לאותה גרסה.
  - ערוך את המניפסט. פתוח `slidia_manifest.xml` בשורש המזלג של Updater CE. הוסף שורה אחת עבור כל דגם שהמהדורה תומכת בו (Y1 ו-Y2 הם הזוג המשותף). ה `repo` הערך הוא של המאגר `owner/repository`; `url` הוא עמוד הפרויקט הציבורי.
  - בדוק את הקטלוג. הפעל את Updater מהקופה הערוכה. בחר Y1 ואשר שהפרויקט מציג את הנכסים Y1. בחר Y2 ואשר שזה מציג את השחרור Y2. סמן את Type A ואת Type B בנפרד כאשר שניהם מתפרסמים.
  - פתח בקשת משיכה. דחף את שינוי המניפסט למזלג שלך ופתח בקשת משיכה כנגד מאגר ה-Upstream CE במעלה הזרם. כלול את קישור הפרויקט, דגמים נתמכים, תג שחרור, שמות נכסים והמכשירים שבדקת.

## צור את שורות המניפסט שלך

מלא את המאגר וסמן כל דגם שהמהדורה תומכת בו. המחולל כותב אחד `<package>` שורה לכל דגם וכוללת רק את התכונות שהגדרת, כך שהתוצאה תואמת את הנוכחי `slidia_manifest.xml` פוּרמָט. כל תכונה ש- Updater CE קורא זמינה למטה - האופציונליים נמצאים מתחת אפשרויות נוספות.כתובת האתר של מאגרהמאגר הציבורי GitHub. הגנרטור מחלץ `owner/repository` מכתובת האתר.שם תוכנהמוצג באפליקציה ובקטלוג האתר.כתובת האתר של הפרויקטדף הפונה לאדם עבור הפרויקט או הערות השחרור שלו.מותגנקה זאת כדי להשתמש במותג ברירת המחדל של הדגם. Keep Data מוצע רק כאשר הקושחה הנכנסת והקושחה המותקנת זהות או חולקות א `derivative` שורש. השתמש בדגל רק כאשר נתוני המשתמש באמת אינם יכולים להעביר.אפשרויות נוספות: אייקון, גרפיקה, נכסי שחרור, לאחר התקנה ומראות

### שלח את השורות כבקשת משיכה
  - העתק את השורות שנוצרו למעלה. הם כבר תואמים לפורמט המניפסט האחרון.
  - ערוך `slidia_manifest.xml` במאגר. השתמש בקישור העריכה למטה; מארח המאגר יוצר עבורך מזלג וענף באופן אוטומטי.
  - הדבק את השורות ממש לפני `</slidia>`, שמירה על הערכים הקיימים ללא שינוי.
  - התחייבו לסניף חדש (לדוגמה `add-your-firmware`), ולאחר מכן פתח בקשת משיכה כנגד מאגר Updater CE.
  - ב-PR, כלול קישור הפרויקט, הדגמים הנתמכים, תג ההפצה, שמות הנכסים והמכשירים שבדקת.

## קל לאמת את השחרור

תן לשחרור תג ברור והערת שחרור. התג שימושי לאנשים, אבל שמות נכסי ה-ZIP הם מה שבהם Updater CE משתמש כדי לזהות את חבילות ההתקנה.

### רשימת שחרור
  - פרסם את המהדורה בפומבי.
  - צרף את קובצי ה-ZIP כנכסי שחרור.
  - ציינו את הדגם הנתמך ואת Type A או Type B בהערות.
  - רשום כל הכנה נדרשת או מגבלות ידועות.

### שחרור אחד, שלושה נכסים

גרסה משותפת יכולה להכיל `rom.zip`, `rom_type_b.zip`, ו `rom_y2.zip`. Updater מסווג אותם בנפרד ובוחר מבין מסנני הדגם והחומרה.

### אין לצרור ניחושים

אל תכלול חבילה Y1 תחת שם הקובץ Y2, או הוסף נתוני פיזור, טוען מראש או מחיצה שלא נבדקו רק כדי לגרום לנכס להופיע.

## מדוע ערכי הדגם חשובים במהלך ההבהוב

המניפסט אינו רק תפריט הורדה. לאחר החילוץ, Updater CE משתמש במודל שנפתר כדי להכין את נתיב ההתקנה התואם. ל-Y1 ו-Y2 יש קבצי פלטפורמה שונים, מטמינים מראש, תצורת פיזור ופריסות מכשירים.
  - Y1: המעדכן מכין את הנתיב Y1 ומשתמש במחיצות השמות של המכשיר כאשר נעשה שימוש ב-MTKClient.
  - Y2: המעדכן מכין את הנתיב Y2 ומשתמש בתצורת Y2 MT6582. שחזור מלא יכול להשתמש בכתובות פיזיות מנתוני הפיזור הנכונים לדגם.
  - תמיכה בין פלטפורמות: Updater CE מטפל בהבהוב מקורי ישירות על פני Windows, Linux ו-macOS (תומך גם במחשבי Intel ו- Apple Silicon Mac) ללא כלים מהבהבים נוספים.
התורמים צריכים לספק קבצי קושחה נכונים, לא קיזוז הבזק. אל תערוך כתובות פיזור, טעינות מוקדמות, קבצי DA או פקודות מחיצה כדי לעקוף חבילה גרועה. תקן את נכס השחרור ובדוק את הדגם המיועד.

## לפני שאתה מבקש מיזוג
  - אמת את ה-XML עם מנתח XML. ציטוט חסר או סגירה `/>` יכול להסתיר כל ערך אחריו.
  - הפעל את העדכון מהקופה שלך כך שיטען את המניפסט המקומי לפני הרענון מרחוק.
  - סמן את Y1 ו-Y2 באופן עצמאי. אשר שהפרויקט מופיע רק במקום שבו החבילה שלו נתמכת.
  - בדוק את רשימת השחרורים עבור `rom.zip`, `rom_type_b.zip`, ו `rom_y2.zip` לפי העניין.
  - בדוק את ההתקנה בפועל במכשיר המיועד, עם כבל נתונים אמין USB ותוכנית שחזור לחזרה לתוכנה המקורית.
  - בבקשת המשיכה, הסבירו מה בדקתם. אין לתאר דגם שלא נבדק כנתמך.
`python -c "from xml.etree import ElementTree as ET; ET.parse('slidia_manifest.xml'); print('manifest ok')"`

לבדיקה מקומית, הפעל את הפקודה משורש המאגר. הוא מאמת את תחביר ה-XML בלבד; זה לא מוכיח שגרסה מכילה קושחה חוקית או שהתקן בטוח להבהב.
