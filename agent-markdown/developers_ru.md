# Добавьте свою прошивку в Updater CE.

Updater CE — это каталог сообщества и установщик кастомных прошивок. Разработайте свой проект на базе ROM, опубликуйте его как общедоступный репозиторий с правильными ресурсами выпуска, добавьте записи модели в `slidia_manifest.xml`, протестируйте фильтры модели и откройте запрос на включение. Один репозиторий может обслуживать каждую поддерживаемую модель.[Просмотр исходного кода Updater CE](https://github.com/y1-community/Innioasis-Updater)[Просмотрите загрузки программного обеспечения](firmware_ru.html)

## Начать с базы ROM

Базовые ПЗУ предоставляют разработчикам специализированных прошивок чистую основу Android с включенными чипами беспроводной радиосвязи. На Y1 они включают Wi-Fi и GPS наряду с заводскими Bluetooth и FM; на Y2 они включают Wi-Fi, GPS и FM наряду с заводским Bluetooth.Базовые ROM загрузки для разработки индивидуального встроенного ПО, каждая из которых включает версию Android и функции беспроводной связи.[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom.zip)[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom_type_b.zip)[``](https://github.com/y1-community/y2-ata-rom/releases/download/y2-ata/rom_y2.zip)

| Скачать | Устройство | Android | Беспроводные функции |
| --- | --- | --- | --- |
| rom.zip | Y1 · Type A | Android 4.2.2 | Добавляет Wi-Fi и GPS к заводским Bluetooth и FM (FM уже работает на Y1 с завода). Для Y1 игроков, поставлявшихся с ОС версии 2.0.0 или новее. |
| rom_type_b.zip | Y1 · Type B | Android 4.2.2 | Добавляет Wi-Fi и GPS к заводским Bluetooth и FM (FM уже работает на Y1 с завода). Для Y1 игроков, поставлявшихся с ОС более ранней версии, чем 2.0.0. |
| rom_y2.zip | Y2 | Android 4.4.2 | Добавляет Wi-Fi, GPS и FM к заводскому Bluetooth. Радиочип Y2 полностью включен, поэтому FM здесь тоже доступен. |

Эти образы представляют собой стандартную базу Android (AOSP) с включенной беспроводной связью устройства, поэтому специальная прошивка может добавлять сетевые функции вместо замены стека радиосвязи. Они являются практической отправной точкой для описанных ниже этапов публикации.

Имя файла является частью сигнала совместимости. Сохраняйте имена точными и помещайте ZIP-файлы в ресурсы выпуска проекта, а не только в дерево исходного кода репозитория.Имена ZIP-файлов прошивки и поддерживаемые устройства``````

| Объект | Устройство | Аппаратное обеспечение | Значение |
| --- | --- | --- | --- |
| rom.zip | Y1 | Type A | Y1 устройства, поставляемые с ОС 2.0.0 или более поздней версии. |
| rom_type_b.zip | Y1 | Type B | Y1 устройства, поставляемые с ОС более ранней версии, чем 2.0.0. |
| rom_y2.zip | Y2 | Y2 | Полноустановочный пакет Y2 . Держите его отдельно от Y1 ресурсов. |
Не переименовывайте пакет, чтобы он соответствовал другой модели. Y1 и Y2 используют разные файлы платформы MediaTek и конфигурацию прошивки. Опубликуйте пакет для оборудования, которое он действительно поддерживает.

## Как работает соединение

Средство обновления CE считывает манифест как свой каталог. Каждый `<package>` строка сообщает ему имя проекта, репозиторий, модель и обработчик. Когда пользователь выбирает этот проект, Updater проверяет опубликованные выпуски репозитория и ищет `rom*.zip` объект.

### Манифест

Называет проект и сопоставляет его с моделью. Y1 и Y2 нуждаются в отдельных строках, даже если они используют общий репозиторий.

### Опубликованный выпуск

Содержит устанавливаемые ZIP-ресурсы. Один выпуск может содержать пакеты Y1 Type A, Y1 Type B и Y2 вместе.

### Установка обновления CE

Использует выбранную модель для выбора соответствующего пакета и пути прошивки для конкретной модели. Пользователю не нужно угадывать имя файла.

## Публикация проекта за пять шагов
  - Форк репозитория Updater CE. Создайте свой собственный форк [y1-community/Innioasis-Updater](https://github.com/y1-community/Innioasis-Updater), затем клонируйте свою вилку локально.
  - Подготовьте общедоступный репозиторий прошивки. Убедитесь, что репозиторий является общедоступным и его версия содержит правильные ZIP-ресурсы. Вы можете положить `rom.zip`, `rom_type_b.zip`, и `rom_y2.zip` в одном выпуске, если они принадлежат одной и той же версии.
  - Отредактируйте манифест. Открыть `slidia_manifest.xml` в корне вашей вилки Updater CE. Добавьте по одной строке для каждой модели, поддерживаемой выпуском (Y1 и Y2 — общая пара). `repo` значение — это репозиторий `owner/repository`; `url` — это общедоступная страница проекта.
  - Протестируйте каталог. Запустите Updater из отредактированной кассы. Выберите Y1 и подтвердите, что в проекте показаны ресурсы Y1. Выберите Y2 и подтвердите, что отображается версия Y2. Проверьте Type A и Type B отдельно, если оба опубликованы.
  - Откройте запрос на вытягивание. Отправьте изменение манифеста в свою вилку и откройте запрос на включение в вышестоящий репозиторий Updater CE. Укажите ссылку на проект, поддерживаемые модели, тег выпуска, названия активов и протестированные вами устройства.

### Отправьте строки как запрос на включение
  - Скопируйте сгенерированные строки выше. Они уже соответствуют последнему формату манифеста.
  - Редактировать `slidia_manifest.xml` в репозитории. Используйте ссылку редактирования ниже; хост репозитория автоматически создает для вас вилку и ветку.
  - Вставьте строки непосредственно перед `</slidia>`, сохранение существующих записей без изменений.
  - Перейдите в новую ветку (например `add-your-firmware`), затем откройте запрос на включение в репозиторий Updater CE.
  - В PR включить ссылку на проект, поддерживаемые модели, тег выпуска, названия активов и протестированные вами устройства.

## Сделайте выпуск легко проверяемым

Дайте выпуску четкий тег и примечание к выпуску. Тег полезен для людей, но имена ресурсов ZIP — это то, что Updater CE использует для идентификации установочных пакетов.

### Контрольный список релиза
  - Опубликуйте релиз публично.
  - Прикрепите ZIP-файлы в качестве ресурсов выпуска.
  - Укажите поддерживаемую модель и Type A или Type B в примечаниях.
  - Перечислите любую необходимую подготовку или известные ограничения.

### Один релиз, три актива

Общий выпуск может содержать `rom.zip`, `rom_type_b.zip`, и `rom_y2.zip`. Программа обновлений классифицирует их отдельно и выбирает фильтры по модели и оборудованию.

### Не группируйте догадки

Не включайте пакет Y1 под именем файла Y2 и не добавляйте непроверенные данные разброса, предварительного загрузчика или раздела только для того, чтобы актив появился.

## Почему записи модели имеют значение при перепрошивке

Манифест — это не просто меню загрузки. После извлечения Updater CE использует решенную модель для подготовки соответствующего пути установки. Y1 и Y2 имеют разные файлы платформы, предварительные загрузчики, конфигурацию разброса и макеты устройств.
  - Y1: программа обновления подготавливает путь Y1 и использует именованные разделы устройства, когда используется MTKClient.
  - Y2: программа обновления подготавливает путь Y2 и использует конфигурацию Y2 MT6582. Полное восстановление может использовать физические адреса из данных разброса, соответствующих модели.
  - Кроссплатформенная поддержка: Updater CE выполняет встроенную прошивку непосредственно в Windows, Linux и macOS (поддерживает компьютеры Mac Intel и Apple Silicon) без дополнительных инструментов для прошивки.
Участники должны предоставлять правильные файлы прошивки, а не смещения прошивки. Не редактируйте адреса разброса, файлы предварительной загрузки, файлы DA или команды разделов, чтобы обойти плохой пакет. Исправьте актив выпуска и протестируйте его на предполагаемой модели.

## Прежде чем запросить слияние
  - Проверьте XML с помощью синтаксического анализатора XML. Отсутствует цитата или завершение `/>` может скрыть каждую запись после нее.
  - Запустите программу обновления из оформления заказа, чтобы она загружала локальный манифест перед удаленным обновлением.
  - Проверьте Y1 и Y2 независимо. Убедитесь, что проект появляется только там, где поддерживается его пакет.
  - Проверьте список выпусков на наличие `rom.zip`, `rom_type_b.zip`, и `rom_y2.zip` в зависимости от обстоятельств.
  - Проверьте фактическую установку на предполагаемом устройстве с помощью надежного кабеля для передачи данных USB и плана восстановления для возврата к исходному программному обеспечению.
  - В запросе на включение объясните, что вы тестировали. Не описывайте непроверенную модель как поддерживаемую.
`python -c "from xml.etree import ElementTree as ET; ET.parse('slidia_manifest.xml'); print('manifest ok')"`

Для локальной проверки запустите эту команду из корня репозитория. Он проверяет только синтаксис XML; это не доказывает, что выпуск содержит действительную прошивку или что устройство можно безопасно прошить.
