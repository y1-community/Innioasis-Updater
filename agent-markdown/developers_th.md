# นักพัฒนา | เพิ่มเฟิร์มแวร์ที่กำหนดเองไปที่ Innioasis Updater CE - Innioasis ดาวน์โหลดเฟิร์มแวร์

สำหรับนักพัฒนาเฟิร์มแวร์

# เพิ่มเฟิร์มแวร์ของคุณไปที่ Updater CE

Updater CE เป็นแค็ตตาล็อกชุมชนและโปรแกรมติดตั้งสำหรับเฟิร์มแวร์ที่กำหนดเอง พัฒนาโครงการของคุณจากฐาน ROM เผยแพร่เป็นพื้นที่เก็บข้อมูลสาธารณะด้วยเนื้อหาที่เผยแพร่ที่ถูกต้อง เพิ่มรายการโมเดลไปที่ `slidia_manifest.xml`ทดสอบตัวกรองโมเดล และเปิดคำขอดึง พื้นที่เก็บข้อมูลหนึ่งแห่งสามารถรองรับทุกรุ่นที่รองรับ[ดูแหล่งสัญญาณ Updater CE](https://github.com/y1-community/Innioasis-Updater)[เรียกดูการดาวน์โหลดซอฟต์แวร์](firmware_th.html)

## เริ่มจากฐาน ROM

Base ROM ช่วยให้นักพัฒนาเฟิร์มแวร์แบบกำหนดเองมีพื้นฐาน Android ที่ชัดเจนโดยเปิดใช้งานชิปวิทยุไร้สาย ใน Y1 พวกเขาเปิดใช้งาน Wi-Fi และ GPS ควบคู่ไปกับ Bluetooth และ FM จากโรงงาน บน Y2 จะเปิดใช้งาน Wi-Fi, GPS และ FM ควบคู่ไปกับบลูทูธจากโรงงานการดาวน์โหลดพื้นฐาน ROM เพื่อการพัฒนาเฟิร์มแวร์แบบกำหนดเอง โดยที่แต่ละเวอร์ชันเปิดใช้งานคุณสมบัติ Android และคุณสมบัติไร้สาย[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom.zip)[``](https://github.com/y1-community/y1-ata-rom/releases/download/0.1/rom_type_b.zip)[``](https://github.com/y1-community/y2-ata-rom/releases/download/y2-ata/rom_y2.zip)

| ดาวน์โหลด | อุปกรณ์ | Android | คุณสมบัติไร้สาย |
| --- | --- | --- | --- |
| rom.zip | Y1 · Type A | Android 4.2.2 | เพิ่ม Wi-Fi และ GPS ให้กับ Bluetooth และ FM จากโรงงาน (FM ใช้งานได้แล้วใน Y1 จากโรงงาน) สำหรับผู้เล่น Y1 ที่มาพร้อมกับ OS 2.0.0 หรือใหม่กว่า |
| rom_type_b.zip | Y1 · Type B | Android 4.2.2 | เพิ่ม Wi-Fi และ GPS ให้กับ Bluetooth และ FM จากโรงงาน (FM ใช้งานได้แล้วใน Y1 จากโรงงาน) สำหรับผู้เล่น Y1 ที่มาพร้อมกับระบบปฏิบัติการที่เก่ากว่า 2.0.0 |
| rom_y2.zip | Y2 | Android 4.4.2 | เพิ่ม Wi-Fi, GPS และ FM ให้กับ Bluetooth จากโรงงาน ชิปวิทยุ Y2 เปิดใช้งานโดยสมบูรณ์ ดังนั้น FM ก็ใช้งานได้ที่นี่เช่นกัน |

รูปภาพเหล่านี้เป็นฐาน Android ในสต็อก (AOSP) ที่เปิดใช้งานวิทยุไร้สายของอุปกรณ์ ดังนั้นเฟิร์มแวร์ที่กำหนดเองจึงสามารถเพิ่มคุณสมบัติเครือข่ายแทนการเปลี่ยนสแต็กวิทยุ เป็นจุดเริ่มต้นที่เป็นประโยชน์สำหรับขั้นตอนการเผยแพร่ด้านล่าง

## ใช้ชื่อเนื้อหาที่เผยแพร่เหล่านี้

ชื่อไฟล์เป็นส่วนหนึ่งของสัญญาณความเข้ากันได้ รักษาชื่อให้ถูกต้องและใส่ไฟล์ ZIP ไว้ในเนื้อหาที่เผยแพร่ของโปรเจ็กต์ ไม่ใช่แค่ในแผนผังแหล่งที่มาของที่เก็บชื่อสินทรัพย์ ZIP เฟิร์มแวร์และอุปกรณ์ที่รองรับ``````

| สินทรัพย์ | อุปกรณ์ | ฮาร์ดแวร์ | ความหมาย |
| --- | --- | --- | --- |
| rom.zip | Y1 | Type A | Y1 อุปกรณ์ที่มาพร้อมกับ OS 2.0.0 หรือใหม่กว่า |
| rom_type_b.zip | Y1 | Type B | Y1 อุปกรณ์ที่มาพร้อมกับระบบปฏิบัติการที่เก่ากว่า 2.0.0 |
| rom_y2.zip | Y2 | Y2 | แพ็คเกจการติดตั้งแบบเต็ม Y2 แยกออกจากสินทรัพย์ Y1 |
อย่าเปลี่ยนชื่อแพ็คเกจเพื่อให้พอดีกับรุ่นอื่น Y1 และ Y2 ใช้ไฟล์แพลตฟอร์ม MediaTek ที่แตกต่างกันและการกำหนดค่าการกะพริบ เผยแพร่แพ็คเกจสำหรับฮาร์ดแวร์ที่รองรับจริง

## การเชื่อมต่อทำงานอย่างไร

Updater CE อ่านรายการเป็นแคตตาล็อก แต่ละ `<package>` บรรทัดบอกชื่อโปรเจ็กต์ พื้นที่เก็บข้อมูล โมเดล และตัวจัดการ เมื่อผู้ใช้เลือกโปรเจ็กต์นั้น Updater จะตรวจสอบรีลีสที่เผยแพร่ของพื้นที่เก็บข้อมูลและค้นหา `rom*.zip` สินทรัพย์.

### ประจักษ์

ตั้งชื่อโปรเจ็กต์และแมปกับโมเดล Y1 และ Y2 จำเป็นต้องมีบรรทัดแยกกัน แม้ว่าพวกเขาจะแชร์ที่เก็บก็ตาม

### เผยแพร่เผยแพร่แล้ว

มีเนื้อหา ZIP ที่สามารถติดตั้งได้ การเผยแพร่ครั้งเดียวอาจมีแพ็กเกจ Y1 Type A, Y1 Type B และ Y2 เข้าด้วยกัน

### Updater CE ติดตั้ง

ใช้รุ่นที่เลือกเพื่อเลือกแพ็คเกจที่ตรงกันและเส้นทางการกะพริบเฉพาะรุ่น ผู้ใช้ไม่ควรต้องเดาชื่อไฟล์

## เผยแพร่โครงการในห้าขั้นตอน
  - แยกที่เก็บ Updater CE สร้างทางแยกของคุณเอง [y1-community/Innioasis-Updater](https://github.com/y1-community/Innioasis-Updater)จากนั้นโคลนส้อมของคุณภายในเครื่อง
  - เตรียมพื้นที่เก็บข้อมูลเฟิร์มแวร์สาธารณะ ตรวจสอบให้แน่ใจว่าที่เก็บเป็นแบบสาธารณะและการเผยแพร่มีเนื้อหา ZIP ที่ถูกต้อง คุณสามารถใส่ `rom.zip`, `rom_type_b.zip`และ `rom_y2.zip` ในรุ่นเดียวกันเมื่ออยู่ในเวอร์ชันเดียวกัน
  - แก้ไขรายการ เปิด `slidia_manifest.xml` ในรากของทางแยก Updater CE ของคุณ เพิ่มหนึ่งบรรทัดสำหรับแต่ละรุ่นที่รองรับรุ่น (Y1 และ Y2 เป็นคู่ทั่วไป) ที่ `repo` ค่าเป็นของที่เก็บ `owner/repository`; `url` เป็นหน้าโครงการสาธารณะ
  - ทดสอบแค็ตตาล็อก เรียกใช้ Updater จากการชำระเงินที่แก้ไข เลือก Y1 และยืนยันว่าโครงการแสดงสินทรัพย์ Y1 เลือก Y2 และยืนยันว่าแสดงรุ่น Y2 ตรวจสอบ Type A และ Type B แยกกันเมื่อมีการเผยแพร่ทั้งสองรายการ
  - เปิดคำขอดึง พุชการเปลี่ยนแปลงรายการไปยังทางแยกของคุณและเปิดคำขอดึงกับที่เก็บอัปสตรีม Updater CE รวมลิงก์โปรเจ็กต์ รุ่นที่รองรับ แท็กการเผยแพร่ ชื่อสินทรัพย์ และอุปกรณ์ที่คุณทดสอบ

## สร้างรายการรายการของคุณ

กรอกข้อมูลลงในที่เก็บและทำเครื่องหมายทุกรุ่นที่รีลีสรองรับ เครื่องกำเนิดไฟฟ้าเขียนอันหนึ่ง `<package>` บรรทัดต่อรุ่นและรวมเฉพาะแอตทริบิวต์ที่คุณกำหนดไว้ ดังนั้นผลลัพธ์จึงตรงกับปัจจุบัน `slidia_manifest.xml` รูปแบบ การอ่านแอตทริบิวต์ Updater CE ทุกรายการมีให้ด้านล่าง — ตัวเลือกเสริมอยู่ใต้ ตัวเลือกเพิ่มเติม.URL ที่เก็บพื้นที่เก็บข้อมูลสาธารณะ GitHub เครื่องกำเนิดสารสกัด `owner/repository` จาก URLชื่อซอฟต์แวร์แสดงในแอปและแค็ตตาล็อกไซต์URL โครงการหน้าพบปะผู้คนสำหรับโปรเจ็กต์หรือบันทึกประจำรุ่นยี่ห้อล้างข้อมูลนี้เพื่อใช้แบรนด์เริ่มต้นของโมเดล SR1, Q3, Q5 และ Q3e เป็นรุ่น Timmkooอุปกรณ์ (แต่ละบรรทัด)Y1Y2A5G1G3G5R1PR1SR1Q3Q5Q3eรุ่นอื่นๆสำหรับรุ่นที่ไม่ได้ระบุไว้ข้างต้น โมเดลที่รู้จักจะเก็บการสะกดแค็ตตาล็อกไว้ธง`do_not_keep_data` — อย่าเสนอ Keep Data สำหรับเฟิร์มแวร์นี้สร้างจากซอฟต์แวร์ดั้งเดิม — เพิ่ม `derivative="y1-community/y1-stock-rom"`

Keep Data จะมีให้เฉพาะเมื่อเฟิร์มแวร์ขาเข้าและเฟิร์มแวร์ที่ติดตั้งเหมือนกันหรือใช้ร่วมกัน `derivative` ราก. ใช้แฟล็กเฉพาะเมื่อข้อมูลผู้ใช้ไม่สามารถถ่ายโอนได้อย่างแท้จริงตัวเลือกเพิ่มเติม: ไอคอน อาร์ตเวิร์ก เนื้อหาที่เผยแพร่ หลังการติดตั้ง และมิเรอร์

#### ไอคอนและงานศิลปะไฟล์ไอคอนเลือกรูปภาพที่คุณจะส่งไปยังพื้นที่เก็บข้อมูล สิ่งนี้จะแสดงตัวอย่างและสร้าง URL แบบดิบ มันไม่ได้อัพโหลดอะไรเลยเส้นทางไอคอนในพื้นที่เก็บข้อมูลพาธไปยังอิมเมจที่คอมมิต ซึ่งสัมพันธ์กับรูทของที่เก็บสาขาไอคอนURL ไอคอนURL รูปภาพโดยตรง เมื่อว่างเปล่า แอปจะใช้การเผยแพร่ `updater.png` หรือไอคอนที่สร้างขึ้นดูตัวอย่างไอคอนที่เลือก

URL ไอคอนโหมดมืดไอคอนธีมสีเข้มเสริม `image_dark` เป็นนามแฝงที่ยอมรับURL อาร์ตเวิร์กแบบไลท์งานศิลปะรอง ทดลองหลังจากภาพที่วางจำหน่ายและ `icon`.URL อาร์ตเวิร์กสีเข้ม

#### ปล่อยสินทรัพย์ชื่อเนื้อหาที่เผยแพร่ชื่อเดียวสำหรับทุกรุ่นที่เลือก ปล่อยว่างไว้เพื่อใช้ `rom.zip` บน Y1 และ `rom_<model>.zip` ที่อื่นรูปแบบสินทรัพย์Glob ใช้เมื่อไม่ได้ตั้งชื่อรหัสไปรษณีย์ของรุ่น `rom*.zip`.Type A เนื้อหาGlob สำหรับแพ็คเกจ Y1 Type A เมื่อชื่อไม่ได้กล่าวไว้Type B เนื้อหาGlob สำหรับแพ็คเกจ Y1 Type B เมื่อชื่อไม่ได้กล่าวไว้เวอร์ชันแอปขั้นต่ำซ่อนรายการจากบิลด์เก่า Updater CE

#### ลิงก์ มิเรอร์ และตระกูล Keep Dataหน้าหลังการติดตั้งเปิดหลังจากติดตั้งสำเร็จหน้าหลังการติดตั้งที่สองขั้นตอนที่สองที่ไม่บังคับสำหรับคู่มือการตั้งค่าแบบหลายหน้ากระจกเงาแบบมีซิปพกพาคั่นด้วยเครื่องหมายจุลภาค `*-mirror` ที่เก็บที่สร้างแพ็คเกจ Portable Flashing Zipพื้นที่เก็บข้อมูลอนุพันธ์เฟิร์มแวร์รุ่นนี้สร้างขึ้นจาก เฟิร์มแวร์ที่เกี่ยวข้องจะแชร์พาร์ติชันข้อมูล ซึ่งเป็นสิ่งที่ Keep Data ตรวจสอบแหล่งเก็บข้อมูลที่เก็บแอปที่มีการเผยแพร่ซึ่งอธิบายถึงแอปในเฟิร์มแวร์นี้ นอกจากนี้ยังต้องมีหน้าหลังการติดตั้งด้วยAPK พื้นที่เก็บข้อมูลที่เก็บแอปซึ่งมี APK แอปดาวน์โหลดและติดตั้งหลังจากเฟิร์มแวร์

#### แคตตาล็อกพิเศษกระสุนตัวระบุที่เสถียรสำหรับลิงก์และบันทึกการติดตั้งที่บันทึกไว้ โมเดลจะถูกผนวกโดยอัตโนมัติเมื่อมีการเลือกหลายรุ่นคำอธิบาย`<package name="Your Firmware" brand="Innioasis" repo="your-account/your-firmware" device="Y1" url="https://github.com/your-account/your-firmware" type="img" handler="Custom Firmware" /> <package name="Your Firmware" brand="Innioasis" repo="your-account/your-firmware" device="Y2" url="https://github.com/your-account/your-firmware" type="img" handler="Custom Firmware" />`คัดลอกบรรทัด

กำลังโหลดรายการล่าสุด...ดูตัวอย่างรายการล่าสุดโดยเพิ่มบรรทัดของคุณ

เครื่องกำเนิดไฟฟ้าดึงกระแสออกมา `slidia_manifest.xml` จากพื้นที่เก็บข้อมูลนี้และแทรกบรรทัดที่คุณสร้างขึ้นไว้ก่อนหน้า `</slidia>`.

บรรทัดเดียวไม่เพียงพอสำหรับพื้นที่เก็บข้อมูลแบบแบ่งใช้ หากบรรทัด Y2 หายไป ผู้ใช้ Y2 จะไม่ได้รับรายการที่ตรงกับโมเดลแม้ว่า `rom_y2.zip` มีอยู่ในการเปิดตัวโครงการ เช่นเดียวกับรุ่นอื่นๆ ทุกรุ่นที่รุ่นของคุณรองรับ

### ส่งบรรทัดเป็นการร้องขอการดึง
  - คัดลอกบรรทัดที่สร้างขึ้นด้านบน ตรงกับรูปแบบไฟล์ Manifest ล่าสุดแล้ว
  - แก้ไข `slidia_manifest.xml` ในพื้นที่เก็บข้อมูล ใช้ลิงก์แก้ไขด้านล่าง โฮสต์พื้นที่เก็บข้อมูลจะสร้างทางแยกและสาขาให้คุณโดยอัตโนมัติ
  - วางบรรทัดไว้ข้างหน้า `</slidia>`, ทำให้รายการที่มีอยู่ไม่เปลี่ยนแปลง
  - มุ่งมั่นกับสาขาใหม่ (ตัวอย่างเช่น `add-your-firmware`) จากนั้นเปิดคำขอดึงข้อมูลกับที่เก็บ Updater CE
  - ในการประชาสัมพันธ์ได้แก่ ลิงก์โปรเจ็กต์ รุ่นที่รองรับ แท็กปล่อย ชื่อสินทรัพย์ และอุปกรณ์ที่คุณทดสอบ
[แก้ไขรายการ Updater CE](https://github.com/y1-community/Innioasis-Updater/edit/main/slidia_manifest.xml)[ดูรายการล่าสุด](https://github.com/y1-community/Innioasis-Updater/blob/main/slidia_manifest.xml)

เก็บชื่อโมเดลให้เป็นตัวพิมพ์ใหญ่ ใช้ URL ที่แน่นอนของพื้นที่เก็บข้อมูลสาธารณะของคุณ และเก็บไว้ `type="img"` และ `handler="Custom Firmware"` สำหรับรายการเฟิร์มแวร์

## ทำให้การตรวจสอบการปล่อยเป็นเรื่องง่าย

ติดแท็กการเผยแพร่ที่ชัดเจนและบันทึกประจำรุ่น แท็กนี้มีประโยชน์สำหรับผู้ใช้ทั่วไป แต่ชื่อเนื้อหา ZIP คือสิ่งที่ Updater CE ใช้เพื่อระบุแพ็คเกจการติดตั้ง

### รายการตรวจสอบการเปิดตัว
  - เผยแพร่ข่าวประชาสัมพันธ์ต่อสาธารณะ
  - แนบไฟล์ ZIP เป็นเนื้อหาที่เผยแพร่
  - ระบุรุ่นที่รองรับและ Type A หรือ Type B ลงในหมายเหตุ
  - แสดงรายการการเตรียมการที่จำเป็นหรือขีดจำกัดที่ทราบ

### หนึ่งรุ่น สามเนื้อหา

รุ่นที่ใช้ร่วมกันสามารถมีได้ `rom.zip`, `rom_type_b.zip`และ `rom_y2.zip`. ตัวอัพเดตจะแยกประเภทพวกมันแยกกันและเลือกจากตัวกรองรุ่นและฮาร์ดแวร์

### อย่ารวมการคาดเดา

อย่ารวมแพ็คเกจ Y1 ไว้ใต้ชื่อไฟล์ Y2 หรือเพิ่มข้อมูลกระจาย ตัวโหลดล่วงหน้า หรือพาร์ติชั่นที่ยังไม่ทดสอบเพื่อทำให้เนื้อหาปรากฏขึ้น

## เหตุใดรายการโมเดลจึงมีความสำคัญระหว่างการกะพริบ

รายการไม่ได้เป็นเพียงเมนูดาวน์โหลดเท่านั้น หลังจากการแตกข้อมูล Updater CE จะใช้โมเดลที่แก้ไขแล้วเพื่อเตรียมเส้นทางการติดตั้งที่ตรงกัน Y1 และ Y2 มีไฟล์แพลตฟอร์ม ตัวโหลดล่วงหน้า การกำหนดค่าแบบกระจาย และเค้าโครงอุปกรณ์ที่แตกต่างกัน
  - Y1: ผู้อัพเดตจะเตรียมเส้นทาง Y1 และใช้พาร์ติชั่นที่มีชื่อของอุปกรณ์เมื่อใช้ MTKClient
  - Y2: ผู้อัปเดตจะเตรียมเส้นทาง Y2 และใช้การกำหนดค่า Y2 MT6582 การกู้คืนแบบเต็มสามารถใช้ที่อยู่ทางกายภาพจากข้อมูลกระจายที่ถูกต้องตามแบบจำลอง
  - การสนับสนุนข้ามแพลตฟอร์ม: Updater CE จัดการการแฟลชดั้งเดิมได้โดยตรงบน Windows, Linux และ macOS (รองรับทั้ง Intel และ Apple Silicon Macs) โดยไม่ต้องใช้เครื่องมือการแฟลชเพิ่มเติม
ผู้ร่วมให้ข้อมูลควรจัดเตรียมไฟล์เฟิร์มแวร์ที่ถูกต้อง ไม่ใช่ออฟเซ็ตแฟลช อย่าแก้ไขที่อยู่กระจาย ตัวโหลดล่วงหน้า ไฟล์ DA หรือคำสั่งพาร์ติชันเพื่อแก้ไขแพ็คเกจที่ไม่ดี แก้ไขเนื้อหาที่เผยแพร่และทดสอบกับโมเดลที่ต้องการ

## ก่อนที่คุณจะขอรวม
  - ตรวจสอบความถูกต้องของ XML ด้วยตัวแยกวิเคราะห์ XML ใบเสนอราคาหรือการปิดการขายหายไป `/>` สามารถซ่อนทุกรายการหลังจากนั้น
  - เปิดตัวอัปเดตจากการชำระเงินของคุณเพื่อโหลดรายการในเครื่องก่อนที่จะรีเฟรชระยะไกล
  - ตรวจสอบ Y1 และ Y2 แยกกัน ยืนยันว่าโปรเจ็กต์ปรากฏเฉพาะในกรณีที่รองรับแพ็คเกจเท่านั้น
  - ตรวจสอบรายการวางจำหน่ายสำหรับ `rom.zip`, `rom_type_b.zip`และ `rom_y2.zip` ตามความเหมาะสม
  - ทดสอบการติดตั้งจริงบนอุปกรณ์ที่ต้องการด้วยสายเคเบิลข้อมูล USB ที่เชื่อถือได้และแผนการกู้คืนสำหรับการกลับไปใช้ซอฟต์แวร์ต้นฉบับ
  - ในคำขอดึง ให้อธิบายสิ่งที่คุณทดสอบ อย่าอธิบายโมเดลที่ยังไม่ทดสอบว่ารองรับ
`python -c "from xml.etree import ElementTree as ET; ET.parse('slidia_manifest.xml'); print('manifest ok')"`

สำหรับการตรวจสอบในเครื่อง ให้รันคำสั่งนั้นจากรูทของที่เก็บ ตรวจสอบไวยากรณ์ XML เท่านั้น ไม่ได้พิสูจน์ว่าการเผยแพร่มีเฟิร์มแวร์ที่ถูกต้องหรืออุปกรณ์สามารถแฟลชได้อย่างปลอดภัย
