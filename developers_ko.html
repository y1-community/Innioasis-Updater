펌웨어 개발자용

Updater CE에 펌웨어를 추가하세요.

Updater CE는 맞춤형 펌웨어를 위한 커뮤니티 카탈로그이자 설치 프로그램입니다. 기본 ROM에서 프로젝트를 개발하고 이를 올바른 릴리스 자산과 함께 공개 저장소로 게시하고 모델 항목을 slidia_manifest.xml, 모델 필터를 테스트하고 끌어오기 요청을 엽니다. 하나의 저장소가 지원하는 모든 모델을 제공할 수 있습니다.

업데이터 CE 소스 보기 소프트웨어 다운로드 찾아보기

베이스 ROM에서 시작

기본 ROM은 맞춤형 펌웨어 개발자에게 무선 라디오 칩이 활성화된 깔끔한 Android 기반을 제공합니다. Y1에서는 공장 블루투스 및 FM과 함께 Wi-Fi 및 GPS를 활성화합니다. Y2에서는 공장 Bluetooth와 함께 Wi-Fi, GPS 및 FM을 활성화합니다.

맞춤형 펌웨어 개발을 위한 기본 ROM 다운로드(각각 활성화되는 Android 버전 및 무선 기능 포함)
다운로드장치Android무선 기능
rom.zipY1 · Type AAndroid 4.2.2공장 Bluetooth 및 FM에 Wi-Fi 및 GPS를 추가합니다(FM은 공장에서 이미 Y1에서 작동합니다). OS 2.0.0 이상과 함께 출시된 Y1 플레이어의 경우.
rom_type_b.zipY1 · Type BAndroid 4.2.2공장 Bluetooth 및 FM에 Wi-Fi 및 GPS를 추가합니다(FM은 공장에서 이미 Y1에서 작동합니다). 2.0.0 이전 OS와 함께 출시된 Y1 플레이어의 경우.
rom_y2.zipY2Android 4.4.2공장 블루투스에 Wi-Fi, GPS, FM을 추가합니다. Y2 라디오 칩이 완전히 활성화되었으므로 여기에서도 FM을 사용할 수 있습니다.

이러한 이미지는 기기 무선 라디오가 활성화된 기본 Android 기반(AOSP)이므로 맞춤 펌웨어는 라디오 스택을 교체하는 대신 네트워크 기능을 추가할 수 있습니다. 이는 아래 게시 단계의 실질적인 시작점입니다.

파일 이름은 호환성 신호의 일부입니다. 이름을 정확하게 유지하고 저장소 소스 트리뿐만 아니라 프로젝트의 릴리스 자산에 ZIP 파일을 넣으세요.

연결 작동 방식

업데이터 CE는 매니페스트를 카탈로그로 읽습니다. 각 <package> 줄은 프로젝트 이름, 저장소, 모델 및 처리기를 알려줍니다. 사용자가 해당 프로젝트를 선택하면 업데이터는 저장소의 게시된 릴리스를 확인하고 rom*.zip 유산.

명백한

프로젝트 이름을 지정하고 모델에 매핑합니다. Y1과 Y2은 저장소를 공유하는 경우에도 별도의 줄이 필요합니다.

출판된 릴리스

설치 가능한 ZIP 자산이 포함되어 있습니다. 단일 릴리스에는 Y1 Type A, Y1 Type B 및 Y2 패키지가 함께 포함될 수 있습니다.

업데이터 CE 설치

선택한 모델을 사용하여 일치하는 패키지와 모델별 플래싱 경로를 선택합니다. 사용자는 파일 이름을 추측할 필요가 없습니다.

5단계로 프로젝트 게시

  1. Updater CE 저장소를 포크합니다. 나만의 포크 만들기 y1-community/Innioasis-Updater을 클릭한 다음 포크를 로컬로 복제하세요.
  2. 공개 펌웨어 저장소를 준비합니다. 저장소가 공개되어 있고 해당 릴리스에 올바른 ZIP 자산이 포함되어 있는지 확인하세요. 당신은 넣을 수 있습니다 rom.zip, rom_type_b.zip, 그리고 rom_y2.zip 동일한 버전에 속하면 동일한 릴리스에 있어야 합니다.
  3. 매니페스트를 편집합니다. 열기 slidia_manifest.xml Updater CE 포크의 루트에 있습니다. 릴리스가 지원하는 각 모델에 대해 한 줄을 추가합니다(Y1 및 Y2은 공통 쌍입니다). 그만큼 repo 값은 저장소의 owner/repository; url 공개 프로젝트 페이지입니다.
  4. 카탈로그를 테스트해 보세요. 편집된 체크아웃에서 Updater를 실행합니다. Y1을 선택하고 프로젝트에 Y1 자산이 표시되는지 확인합니다. Y2를 선택하고 Y2 릴리스가 표시되는지 확인합니다. 둘 다 게시되면 Type A와 Type B를 별도로 확인하세요.
  5. 끌어오기 요청을 엽니다. 매니페스트 변경 사항을 포크로 푸시하고 업스트림 업데이터 CE 저장소에 대한 풀 요청을 엽니다. 프로젝트 링크, 지원되는 모델, 릴리스 태그, 자산 이름, 테스트한 장치를 포함하세요.

데이터 유지는 수신 펌웨어와 설치된 펌웨어가 동일하거나 공유하는 경우에만 제공됩니다. derivative 뿌리. 사용자 데이터가 실제로 전달될 수 없는 경우에만 플래그를 사용하십시오.

자산 출시

선택한 모든 모델에 대해 하나의 이름이 있습니다. 사용하려면 비워두세요. rom.zip Y1에 그리고 rom_<model>.zip 다른 곳.
릴리스의 zip 이름이 지정되지 않은 경우 사용되는 Glob rom*.zip.

Y1 Type B 패키지 이름에 해당 패키지가 명시되지 않은 경우 Glob입니다.

링크, 미러 및 Keep Data 제품군

성공적으로 설치한 후 열었습니다.
여러 페이지로 구성된 설정 가이드를 위한 선택적 두 번째 단계입니다.
쉼표로 구분 *-mirror Portable Flashing Zip 패키지를 빌드하는 저장소.
이 릴리스의 기반이 되는 펌웨어입니다. 관련 펌웨어는 데이터 파티션을 공유하는데, 이는 Keep Data가 확인하는 것입니다.
이 펌웨어의 앱을 설명하는 릴리스의 앱 저장소입니다. 또한 설치 후 페이지가 필요합니다.
APK 앱이 펌웨어 이후에 다운로드 및 설치되는 앱 저장소입니다.

카탈로그 추가사항

링크 및 저장된 설치 기록에 대한 안정적인 식별자입니다. 여러 모델을 선택하면 해당 모델이 자동으로 추가됩니다.

매니페스트가 읽는 모든 속성

      
이는 현재 Updater CE 빌드가 이해하는 특성입니다. 생성기는 사용자가 입력한 항목만 작성합니다. 앱은 나머지 부분에 대해 합리적인 기본값으로 돌아갑니다.

      

        

          slidia_manifest.xml 패키지 속성 및 의미
          
            
기인하다필요기능

          
          
            
name예카탈로그와 설치 카드에 표시된 소프트웨어 이름입니다.

            
repo예owner/repo. 앱은 해당 저장소의 GitHub 릴리스를 읽습니다.

            
device예대상 모델, 대문자(Y1, Y2, G1, Q3e, …). 모델당 하나의 항목을 유지합니다.

            
url추천카탈로그에서 프로젝트 페이지 또는 릴리스 노트가 열립니다.

            
type, handler예, 실제로는type="img" 그리고 handler="Custom Firmware". 다른 유형 및 비펌웨어 처리기는 건너뜁니다.

            
brand선택사항카탈로그 브랜드(Innioasis, Timmkoo). 비어 있음은 모델의 기본 브랜드를 사용합니다.

            
package_name선택사항릴리스 자산 파일 이름. 기본값은 rom.zip Y1에 그리고 rom_<model>.zip 다른 모델에서는.

            
asset_pattern선택사항펌웨어 zip 이름이 지정되지 않은 릴리스의 경우 대소문자를 구분하지 않는 glob rom*.zip (예를 들어 my-firmware-*.zip).

            
type_a_asset, type_b_asset선택사항파일 이름에 일반적인 마커가 포함되지 않은 경우 Y1 Type A 및 Type B zip을 식별하는 글로브입니다.

            
icon선택사항로고 URL. 릴리스 자체 이후에 사용됨 updater.png / updater.jpg, 그리고 모든 릴리스에 대한 대체 수단으로 사용됩니다.

            
icon_dark선택사항어두운 테마 로고. image_dark 허용되는 별칭입니다.

            
image선택사항보조 조명 아트웍, 이후 시도 icon.

            
post_install, post_install2선택사항성공적인 설치 후 페이지가 열렸습니다. 두 번째는 다단계 가이드를 다룹니다.

            
portable_zips선택사항쉼표로 구분 *-mirror 즉시 실행 가능한 휴대용 패키지를 게시하는 저장소입니다.

            
derivative선택사항펌웨어가 빌드된 리포지토리입니다. 동일한 파생 루트를 가진 펌웨어는 사용자 데이터를 유지할 수 있습니다.

            
info_repo선택사항펌웨어가 배포하는 내용을 설명하는 릴리스가 있는 앱 저장소입니다. 필요하다 post_install 또는 post_install2.

            
apk_repo선택사항펌웨어 이후에 앱이 설치되는 APK 앱 저장소입니다.

            
min_version선택사항Updater CE가 이 버전보다 오래된 경우 항목을 숨깁니다.

            
do_not_keep_data선택사항true (또한 1 / yes)는 이 펌웨어에 대해 데이터를 완전히 유지하는 것을 차단합니다.

            
slug선택사항링크 및 저장된 설치 기록에 대한 안정적인 식별자입니다. 비어 있으면 이름과 모델에서 생성됩니다.

            
description선택사항짧은 카탈로그 설명. 속성 값 또는 요소의 텍스트일 수 있습니다.

          
        

      

      
호환성을 위해 기존 이름을 계속 읽습니다. model, package, portable_zip, post_install_2, min_app_version 그리고 image_dark. 새 항목은 위의 현재 이름을 사용해야 합니다.

플래싱 중에 모델 항목이 중요한 이유

      
매니페스트는 단순한 다운로드 메뉴가 아닙니다. 추출 후 Updater CE는 확인된 모델을 사용하여 일치하는 설치 경로를 준비합니다. Y1과 Y2에는 서로 다른 플랫폼 파일, 프리로더, 스캐터 구성 및 장치 레이아웃이 있습니다.

      
    
        
  • Y1: 업데이트 프로그램은 Y1 경로를 준비하고 MTKClient이 사용될 때 장치의 명명된 파티션을 사용합니다.
    • 
        
  • Y2: 업데이트 프로그램은 Y2 경로를 준비하고 Y2 MT6582 구성을 사용합니다. 전체 복구는 모델에 맞는 분산 데이터의 물리적 주소를 사용할 수 있습니다.
    • 
        
  • 크로스 플랫폼 지원: Updater CE는 추가 플래싱 도구 없이 Windows, Linux 및 macOS(Intel 및 Apple Silicon Mac 모두 지원)에서 직접 기본 플래싱을 처리합니다.
    • 
      

      
기여자는 플래시 오프셋이 아닌 올바른 펌웨어 파일을 제공해야 합니다. 잘못된 패키지를 해결하기 위해 분산 주소, 프리로더, DA 파일 또는 파티션 명령을 편집하지 마십시오. 릴리스 자산을 수정하고 의도한 모델에서 테스트합니다.
