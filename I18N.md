# Multilingual site: how it works and how to work on it

Applies to **innioasis.app** (this repository, `y1-community/Innioasis-Updater`)
and **themes.innioasis.app** (`y1-community/InnioasisY1Themes`). The two sites
share one runtime, one catalog format and one reviewable translation bundle.

> **Rule for every agent and human: content changes ship in all languages at
> once.** Adding a page, changing a sentence, or renaming a button is never
> finished until the English source is re-extracted and every catalog has the
> new string. The pipeline makes this one command; see *After changing copy*.

## What is live

| Piece | Where | State |
| --- | --- | --- |
| Language picker in the bottom dock | `site-locale.js`, `support_toolbar.html` | On both sites |
| Locale catalogs | `i18n/catalogs/<code>.json` | ~270 languages, growing daily |
| Hand-reviewed UI copy | `i18n/reviewed/core-ui.json` | 20 strings x 25 major languages |
| Runtime translation of new content | `site-locale.js` MutationObserver | Release notes, READMEs, firmware lists |
| GA4 / GTM language events | `site-locale.js` | `site_language_view`, `site_language_change` |
| Static locale copies for SEO | `scripts/i18n/prerender.py` -> `dist/` | Built in CI, uploaded as an artifact |
| Automated top-up | `.github/workflows/update-translations.yml` | Push, daily, dispatch |
| donors.csv & notice.xml sync | `.github/workflows/sync-donors.yml` (both repos) | Updater -> Themes, automated |

## Language switching

`site-locale.js` runs on every page. It resolves the language from, in order:

1. the URL prefix (`/de/index.html`),
2. `?lang=de`,
3. the visitor's stored choice (`localStorage.innioasis-locale`),
4. `navigator.languages`.

It then loads only that catalog, translates text nodes plus `title`, `alt`,
`placeholder`, `aria-label` and the meta description, and sets `<html lang>` and
`dir` (so Arabic, Hebrew, Persian, Urdu, Pashto, Sindhi, Uyghur, Divehi, Kurdish
Sorani, Yiddish and Malay Jawi render right-to-left). English visits fetch no
catalog.

The control lives in the support dock (`data-locale-open`), with a
`nav-tools` fallback and a floating fallback if a page has no dock. The dock is
injected after load, so the runtime binds it on the `y1-dock-slot-ready` event.

For programmatic content, use the public API rather than a second translator:

```js
InnioasisLocale.locale            // "de"
InnioasisLocale.translate(text)   // catalog lookup, English fallback
InnioasisLocale.refresh()         // re-apply after replacing a large subtree
InnioasisLocale.set("ja")         // same behaviour as the picker
```

## Translation pipeline

```bash
python3 scripts/i18n/harvest_ui_strings.py              # copy rendered by JS
python3 scripts/i18n/extract_strings.py --tiers core,full
python3 scripts/i18n/seed_catalogs.py                   # reviewed bundle wins
python3 scripts/i18n/translate.py --locales core --top 700
python3 scripts/i18n/translate.py --index-only          # rebuild the picker
python3 scripts/i18n/translate.py --check                # coverage report
python3 scripts/i18n/prerender.py --locales all --tiers core --out dist
```

`translate.py` is incremental: a catalog on disk is the cache, so an interrupted
run resumes and an edited sentence costs one request. `--top N` translates the
N most-used strings first — the best coverage per request. Providers are
configurable in `i18n/config.json`; the default is Google's public, keyless
endpoint. A keyed provider (`GOOGLE_TRANSLATE_API_KEY`, `DEEPL_API_KEY`) can be
selected without changing any catalog.

Brand names in `protectedTerms` are masked before a request and restored after,
so "Solar" never becomes the sun and "Rondo" never becomes a musical form.

### After changing copy

1. Edit the English page (or the generator that produces it).
2. Run extraction, then `translate.py --locales all` (or let CI do it).
3. Run `--index-only` so a newly translated language appears in the picker.
4. Never leave a language behind because it was "only a small edit".

### Adding a language

Add the code to `i18n/locales.json` (base languages in `locales`, regional
flavours in `variants`), then run extraction and `translate.py --locales <code>`.
`--index-only` publishes it to the picker. The catalog is a plain JSON file of
`"English source": "translation"` pairs, so a native-speaker review is a direct
edit that the translator will not overwrite.

## Quality rules

- Protected terms stay verbatim (Innioasis, Timmkoo, Rockbox, Updater CE, Solar,
  Rondo, Koensayr, Inniclassic, Y2Player, Better-Y, Y2Linux, SP Flash Tool).
- Translate meaning, not word order. Keep the site's plain, practical tone; no
  hype, no idioms that do not travel, no jokes at the reader's expense.
- Safety copy (power off, connect only at the prompt, back up first) must stay
  as unambiguous as the English. Never soften a warning.
- Regional editions (`i18n/regions.json`) decide what a region may offer, not
  just its language: mainland China hides the Updater app and Discord/PayPal/
  GitHub; Russia and Iran hide Discord, PayPal and GitHub; India hides TikTok.
  Apply these with `data-availability` / `data-region-only` attributes.
- A machine translation is a starting point, not a review. The reviewed bundle
  is where corrections belong.

## Static copies and SEO

`prerender.py` writes `dist/<locale>/<page>.html` with the text already
translated, `lang`/`dir` set, canonical and `og:url` pointing at the locale copy,
and `hreflang` alternates. Assets become root-absolute so every locale shares one
CSS/JS/image tree. `dist/` is generated, never committed.

CI uploads it as the `i18n-site` artifact. Publishing it is deliberately opt-in:
run **Update site translations** with `deploy_pages` checked, which builds
English + every locale and deploys through GitHub Pages. Until hosting is pointed
at that build, translations still work at runtime on the live site; only the
crawlable copies wait for the deploy.

## GA4

Every page already loads the Google Tag Manager container (`GTM-TNDGC37L`), which
carries the GA4 property. The runtime adds the parameters GA4 cannot infer from a
URL, because the language is swapped in place:

- `site_language_view` — fired once per page with `site_language`, `site_region`,
  `page_path`.
- `site_language_change` — fired when a visitor picks a language.
- `site_language` user property, updated on boot and on change.

To send GA4 page views directly instead of through GTM, add
`<meta name="ga4-measurement-id" content="G-XXXXXXXXXX">` (or set
`window.INNIOASIS_GA4_ID`). The runtime then loads `gtag.js` with
`send_page_view: false` and sends one page view per language, avoiding the
double-counting that a hard-coded tag would cause.

## donors.csv and notice.xml

`donors.csv` and `notice.xml` are owned canonically by this repository. `sync-donors.yml` normalises
both to LF line endings and commits any changes. When a cross-repo token (`DONORS_SYNC_TOKEN`) is configured,
it immediately mirrors both files to `y1-community/InnioasisY1Themes`.
The Themes repository runs its own automated sync workflow (`sync-donors.yml` every 30 minutes, on dispatch,
and on push) to pull both files from canonical sources (GitHub raw, live innioasis.app, and GitHub REST API)
and merge updates automatically into `main`.

## Parallel work (Antigravity and other agents)

This work was built alongside Antigravity. To avoid stepping on each other:

- **Take `I18N_TODO.md` before editing.** Claim a line by putting your name on
  it; tick it when verified.
- Do not hand-edit `i18n/catalogs/*.json` except to fix a reviewed translation.
  Run the pipeline instead; it preserves reviewed values unless `--force`.
- Shared files are `site-locale.js`, `site-locale.css`,
  `i18n/reviewed/*.json`, `scripts/i18n/*.py`. Copy them between repos only
  from `Innioasis-Updater` — it is the source of truth; the Themes repo mirrors
  them.
- Theme browsing lives at https://themes.innioasis.app/. This repository no
  longer ships a theme downloader page; the Themes repository owns theme copy.
- Announce in `I18N_TODO.md` when you change a generator template, because that
  changes the strings extraction sees for every generated page.

## Runtime fallback: anything a catalog does not contain

Catalogs are the fast path. Whatever a catalog is missing is translated in the
browser through Google's keyless `translate_a/single` endpoint (`client=gtx`),
the same public endpoint the Updater app uses.

- Scope: text nodes and `aria-label` / `title` / `alt` / `placeholder`
  attributes anywhere in the page body. `PRE`, `CODE`, `KBD`, `SAMP`,
  `TEXTAREA`, `[data-i18n-skip]` and the language panel itself are skipped.
- Cached per language in `localStorage` (`innioasis-dynamic-translations`), so a
  second visit to the same page costs no requests.
- Two requests in flight at most, 800 strings per page view, and the English
  text stays in place if a request fails - a node is never left blank.
- Nodes already replaced from a catalog are marked, so translated text is never
  sent back through the API as if it were English.

## How the language control navigates

Picking a language always loads a page; it never repaints the current document
and leaves the address bar behind. The runtime builds one URL and assigns it:

1. If the page's `hreflang` alternates name the chosen locale, it goes to that
   translated copy, which already carries `lang`/`dir` and the translated HTML.
2. Otherwise it keeps the current path and sets `?lang=<locale>`, which the
   runtime translates after boot.

Either way the URL also carries the visitor's current preferences, so the new
document is painted before its own scripts run: `site_theme` (appearance),
`accent`, `accessibility`, `fontSize`, `donations`, `privacy`,
`privacy_analytics`, `ce` and `dock`. Filters and other query parameters on the
current page are preserved. The shell reads each value on arrival and then
clears the preference parameters with `replaceState`, so the address bar still
shows a clean, shareable URL. `InnioasisLocale.set(code)` behaves exactly like
the picker.

Without a parameter the language comes from the browser's language list first,
then the region default, then the stored choice.
