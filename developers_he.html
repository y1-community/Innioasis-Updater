למפתחי קושחה

הוסף את הקושחה שלך ל-Updater CE.

Updater CE הוא קטלוג הקהילה ומתקין עבור קושחה מותאמת אישית. פתח את הפרויקט שלך מבסיס ROM, פרסם אותו כמאגר ציבורי עם נכסי השחרור הנכונים, הוסף את ערכי המודל ל- slidia_manifest.xml, בדוק את מסנני הדגם ופתח בקשת משיכה. מאגר אחד יכול לשרת כל דגם שהוא תומך בו.

צפה במקור Updater CE עיין בהורדות תוכנה

התחל מבסיס ROM

רכיבי ROM בסיסיים מעניקים למפתחי קושחה מותאמים אישית בסיס אנדרואיד נקי עם שבבי הרדיו האלחוטיים מופעלים. ב-Y1 הם מאפשרים Wi-Fi ו-GPS לצד Bluetooth ו-FM של היצרן; ב-Y2 הם מאפשרים Wi-Fi, GPS ו-FM לצד Bluetooth של היצרן.

הורדות בסיס ROM לפיתוח קושחה מותאם אישית, עם גרסת אנדרואיד ותכונות אלחוטיות שכל אחת מהן מאפשרת
הורדהמכשירAndroidתכונות אלחוטיות
rom.zipY1 · Type AAndroid 4.2.2מוסיף Wi-Fi ו-GPS למפעל Bluetooth ו-FM (FM כבר עובד על Y1 מהמפעל). עבור Y1 נגנים שנשלחו עם מערכת הפעלה 2.0.0 ואילך.
rom_type_b.zipY1 · Type BAndroid 4.2.2מוסיף Wi-Fi ו-GPS למפעל Bluetooth ו-FM (FM כבר עובד על Y1 מהמפעל). עבור Y1 שחקנים שנשלחו עם מערכת הפעלה קודמת מ-2.0.0.
rom_y2.zipY2Android 4.4.2מוסיף Wi-Fi, GPS ו-FM ל-Bluetooth של היצרן. שבב הרדיו Y2 מופעל במלואו, כך ש-FM זמין גם כאן.

תמונות אלה הן בסיס אנדרואיד (AOSP) המניות עם מכשירי הרדיו האלחוטיים מופעלים, כך שקושחה מותאמת אישית יכולה להוסיף תכונות רשת במקום להחליף את מחסנית הרדיו. הם נקודת ההתחלה המעשית לשלבי הפרסום שלהלן.

השתמש בשמות נכסי ההפצה האלה

שם הקובץ הוא חלק מאות התאימות. שמרו על השמות מדויקים והכניסו את קובצי ה-ZIP לנכסי השחרור של הפרויקט, לא רק בעץ המקור של המאגר.

שמות נכסי ZIP של קושחה ומכשירים נתמכים
נכסמכשירחומרהמשמעות
rom.zipY1Type AY1 מכשירים שנשלחו עם מערכת הפעלה 2.0.0 ואילך.
rom_type_b.zipY1Type BY1 מכשירים שנשלחו עם מערכת הפעלה קודמת מ-2.0.0.

אל תשנה שם של חבילה כדי שתתאים לדגם אחר. Y1 ו-Y2 משתמשים בקבצי פלטפורמה שונים MediaTek ובתצורה מהבהבת. פרסם את החבילה עבור החומרה שהיא באמת תומכת בה.

איך החיבור עובד

Updater CE קורא את המניפסט כקטלוג שלו. כל אחד <package> line אומר לו את שם הפרויקט, המאגר, המודל והמטפל. כאשר משתמש בוחר בפרוייקט זה, Updater בודק את המהדורות שפורסמו של המאגר ומחפש א rom*.zip נכס.

מניפסט

נותן שם לפרויקט וממפה אותו למודל. Y1 ו-Y2 צריכים שורות נפרדות, גם כאשר הם חולקים מאגר.

מהדורה שפורסמה

מכיל את נכסי ה-ZIP הניתנים להתקנה. מהדורה בודדת עשויה להכיל את החבילות Y1 Type A, Y1 Type B, ו-Y2 יחד.

התקנת Updater CE

משתמש בדגם שנבחר כדי לבחור את החבילה התואמת ואת נתיב ההבהוב הספציפי לדגם. המשתמש לא צריך לנחש שם קובץ.

פרסם פרויקט בחמישה שלבים

  1. מזלג את מאגר Updater CE. צור מזלג משלך y1-community/Innioasis-Updater, ואז לשבט את המזלג שלך באופן מקומי.
  2. הכן מאגר קושחה ציבורי. ודא שהמאגר הוא ציבורי והשחרור שלו מכיל את נכסי ה-ZIP הנכונים. אתה יכול לשים rom.zip, rom_type_b.zip, ו rom_y2.zip באותה גרסה כשהם שייכים לאותה גרסה.
  3. ערוך את המניפסט. פתוח slidia_manifest.xml בשורש המזלג של Updater CE. הוסף שורה אחת עבור כל דגם שהמהדורה תומכת בו (Y1 ו-Y2 הם הזוג המשותף). ה repo הערך הוא של המאגר owner/repository; url הוא עמוד הפרויקט הציבורי.
  4. בדוק את הקטלוג. הפעל את Updater מהקופה הערוכה. בחר Y1 ואשר שהפרויקט מציג את הנכסים Y1. בחר Y2 ואשר שזה מציג את השחרור Y2. סמן את Type A ואת Type B בנפרד כאשר שניהם מתפרסמים.
  5. פתח בקשת משיכה. דחף את שינוי המניפסט למזלג שלך ופתח בקשת משיכה כנגד מאגר ה-Upstream CE במעלה הזרם. כלול את קישור הפרויקט, דגמים נתמכים, תג שחרור, שמות נכסים והמכשירים שבדקת.

צור את שורות המניפסט שלך

מלא את המאגר וסמן כל דגם שהמהדורה תומכת בו. המחולל כותב אחד <package> שורה לכל דגם וכוללת רק את התכונות שהגדרת, כך שהתוצאה תואמת את הנוכחי slidia_manifest.xml פוּרמָט. כל תכונה ש- Updater CE קורא זמינה למטה - האופציונליים נמצאים מתחת אפשרויות נוספות.

המאגר הציבורי GitHub. הגנרטור מחלץ owner/repository מכתובת האתר.
מוצג באפליקציה ובקטלוג האתר.
דף הפונה לאדם עבור הפרויקט או הערות השחרור שלו.
נקה זאת כדי להשתמש במותג ברירת המחדל של הדגם. SR1, Q3, Q5 ו-Q3e הם Timmkoo דגמים.
מכשירים (שורה אחת כל אחד)
לדגם שאינו מופיע למעלה. דגמים מוכרים שומרים על האיות בקטלוג שלהם.
דגלים

Keep Data מוצע רק כאשר הקושחה הנכנסת והקושחה המותקנת זהות או חולקות א derivative שורש. השתמש בדגל רק כאשר נתוני המשתמש באמת אינם יכולים להעביר.

אפשרויות נוספות: אייקון, גרפיקה, נכסי שחרור, לאחר התקנה ומראות

אייקון ויצירות אמנות

בחר את התמונה שתתחייב למאגר. זה מציג אותו בתצוגה מקדימה ובונה את כתובת האתר הגולמית שלו; זה לא מעלה כלום.
נתיב לתמונה המחויבת, ביחס לשורש המאגר.
כתובת אתר ישירה של תמונה. כשהאפליקציה ריקה, האפליקציה משתמשת במהדורה updater.png או סמל שנוצר.

סמל ערכת נושא כהה אופציונלי. image_dark הוא כינוי מקובל.
יצירת אמנות משנית, נוסתה לאחר תמונת השחרור ו icon.

שחרר נכסים

שם אחד לכל דגם שנבחר. השאר ריק לשימוש rom.zip ב-Y1 ו rom_<model>.zip במקום אחר.
גלוב משמש כאשר הרוכסנים של המהדורה אינם נקראים בשם rom*.zip.
גלוב עבור החבילה Y1 Type A כאשר שמה אינו אומר זאת.
גלוב עבור החבילה Y1 Type B כאשר שמה אינו אומר זאת.
הסתר את הערך ממבנים ישנים יותר של Updater CE.

קישורים, מראות ומשפחת Keep Data

נפתח לאחר התקנה מוצלחת.
שלב שני אופציונלי עבור מדריך התקנה מרובה עמודים.
מופרדים בפסיקים *-mirror מאגרים הבונים חבילות Flashing Zip ניידות.
הקושחה שממנה בנויה מהדורה זו. קושחות קשורות חולקות מחיצת נתונים, וזה מה ש-Keep Data בודק.
ריפו של אפליקציות שהגרסאות שלה מתארות את האפליקציות בקושחה זו. זה גם צריך עמוד לאחר ההתקנה.
ריפו של אפליקציה שהאפליקציה מורידה ומתקין את APK לאחר הקושחה.

תוספות קטלוג

מזהה יציב לקישורים ורשומות התקנה שמורות. הדגם מצורף אוטומטית כאשר נבחרים מספר דגמים.

טוען את המניפסט האחרון...

הצג תצוגה מקדימה של המניפסט האחרון עם השורות שלך

המחולל הביא את הזרם slidia_manifest.xml מהמאגר הזה והכנסת את השורות שנוצרו ממש לפני </slidia>.


          

        

      


      
שורה אחת לא מספיקה למאגר משותף. אם השורה Y2 חסרה, משתמשים Y2 לא יקבלו ערך תואם דגם גם כאשר rom_y2.zip קיים בשחרור הפרויקט. הדבר נכון לגבי כל דגם אחר שהגרסה שלך תומכת בו.


      
כל תכונה שהמניפסט קורא

      
אלו הן התכונות שמבינות ה- Updater CE הנוכחיות. המחולל כותב רק את אלה שאתה ממלא; האפליקציה חוזרת לברירות המחדל הגיוניות עבור השאר.

      

        

          תכונות החבילה slidia_manifest.xml ומשמעותן
          
            
תכונהנחוץמה זה עושה

          
          
            
nameכןשם התוכנה מוצג בקטלוג ובכרטיסי ההתקנה.

            
repoכןowner/repo. האפליקציה קוראת את מהדורות GitHub של המאגר הזה.

            
deviceכןדגם יעד, אותיות רישיות (Y1, Y2, G1, Q3e,…). שמור כניסה אחת לכל דגם.

            
urlמומלץדף הפרויקט או הערות שחרור נפתחו מהקטלוג.

            
type, handlerכן בפועלtype="img" ו handler="Custom Firmware". סוגים אחרים ומטפלים שאינם קושחה מדלגים.

            
brandאופציונלימותג קטלוג (Innioasis, Timmkoo). Empty משתמש במותג ברירת המחדל של הדגם.

            
package_nameאופציונלישחרר את שם הקובץ של הנכס. ברירת מחדל ל rom.zip ב-Y1 ו rom_<model>.zip על דגמים אחרים.

            
asset_patternאופציונליגלוב לא רגיש לאותיות רישיות עבור מהדורות שהקושחה שלהן לא נקראת rom*.zip (לדוגמה my-firmware-*.zip).

            
type_a_asset, type_b_assetאופציונליגלובס המזהים את ה-Y1 Type A ו-Type B zip כאשר שמות הקבצים שלהם אינם מכילים את הסמנים הרגילים.

            
iconאופציונליכתובת אתר של לוגו. בשימוש לאחר המהדורה משלו updater.png / updater.jpg, וכנקודת המוצא לכל מהדורה.

            
icon_darkאופציונלילוגו עם נושא כהה. image_dark הוא כינוי מקובל.

            
imageאופציונלייצירת אמנות קלה משנית, נוסתה לאחר מכן icon.

            
post_install, post_install2אופציונלידפים נפתחו לאחר התקנה מוצלחת. השני מכסה מדריך רב-שלבי.

            
portable_zipsאופציונלימופרדים בפסיקים *-mirror מאגרים המפרסמים חבילות ניידות מוכנות להפעלה.

            
derivativeאופציונלימאגר שממנו בנויה הקושחה. קושחה עם אותו שורש נגזרת יכולה לשמור על נתוני משתמש.

            
info_repoאופציונלימאגר אפליקציות שהגרסאות שלו מתארות את מה שהקושחה פורסת. דורש post_install או post_install2.

            
apk_repoאופציונלימאגר אפליקציות שאת APK האפליקציה מתקינה לאחר הקושחה.

            
min_versionאופציונליהסתר את הערך כאשר Updater CE ישן יותר מגרסה זו.

            
do_not_keep_dataאופציונליtrue (גם 1 / yes) חוסם את Keep Data לחלוטין עבור קושחה זו.

            
slugאופציונלימזהה יציב לקישורים ורשומות התקנה שמורות. נוצר מהשם והדגם כשהם ריקים.

            
descriptionאופציונליתיאור קטלוג קצר. זה יכול להיות ערך התכונה או הטקסט של האלמנט.

          
        

      

      
שמות מדור קודם עדיין נקראים לצורך תאימות: model, package, portable_zip, post_install_2, min_app_version ו image_dark. ערכים חדשים צריכים להשתמש בשמות הנוכחיים שלמעלה.

מדוע ערכי הדגם חשובים במהלך ההבהוב

      
המניפסט אינו רק תפריט הורדה. לאחר החילוץ, Updater CE משתמש במודל שנפתר כדי להכין את נתיב ההתקנה התואם. ל-Y1 ו-Y2 יש קבצי פלטפורמה שונים, מטמינים מראש, תצורת פיזור ופריסות מכשירים.

      
    
        
  • Y1: המעדכן מכין את הנתיב Y1 ומשתמש במחיצות השמות של המכשיר כאשר נעשה שימוש ב-MTKClient.
    • 
        
  • Y2: המעדכן מכין את הנתיב Y2 ומשתמש בתצורת Y2 MT6582. שחזור מלא יכול להשתמש בכתובות פיזיות מנתוני הפיזור הנכונים לדגם.
    •
