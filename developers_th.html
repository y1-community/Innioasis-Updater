สำหรับนักพัฒนาเฟิร์มแวร์

เพิ่มเฟิร์มแวร์ของคุณไปที่ Updater CE

Updater CE เป็นแค็ตตาล็อกชุมชนและโปรแกรมติดตั้งสำหรับเฟิร์มแวร์ที่กำหนดเอง พัฒนาโครงการของคุณจากฐาน ROM เผยแพร่เป็นพื้นที่เก็บข้อมูลสาธารณะด้วยเนื้อหาที่เผยแพร่ที่ถูกต้อง เพิ่มรายการโมเดลไปที่ slidia_manifest.xmlทดสอบตัวกรองโมเดล และเปิดคำขอดึง พื้นที่เก็บข้อมูลหนึ่งแห่งสามารถรองรับทุกรุ่นที่รองรับ

ดูแหล่งสัญญาณ Updater CE เรียกดูการดาวน์โหลดซอฟต์แวร์

เริ่มจากฐาน ROM

Base ROM ช่วยให้นักพัฒนาเฟิร์มแวร์แบบกำหนดเองมีพื้นฐาน Android ที่ชัดเจนโดยเปิดใช้งานชิปวิทยุไร้สาย ใน Y1 พวกเขาเปิดใช้งาน Wi-Fi และ GPS ควบคู่ไปกับ Bluetooth และ FM จากโรงงาน บน Y2 จะเปิดใช้งาน Wi-Fi, GPS และ FM ควบคู่ไปกับบลูทูธจากโรงงาน

การดาวน์โหลดพื้นฐาน ROM เพื่อการพัฒนาเฟิร์มแวร์แบบกำหนดเอง โดยที่แต่ละเวอร์ชันเปิดใช้งานคุณสมบัติ Android และคุณสมบัติไร้สาย
ดาวน์โหลดอุปกรณ์Androidคุณสมบัติไร้สาย
rom.zipY1 · Type AAndroid 4.2.2เพิ่ม Wi-Fi และ GPS ให้กับ Bluetooth และ FM จากโรงงาน (FM ใช้งานได้แล้วใน Y1 จากโรงงาน) สำหรับผู้เล่น Y1 ที่มาพร้อมกับ OS 2.0.0 หรือใหม่กว่า
rom_type_b.zipY1 · Type BAndroid 4.2.2เพิ่ม Wi-Fi และ GPS ให้กับ Bluetooth และ FM จากโรงงาน (FM ใช้งานได้แล้วใน Y1 จากโรงงาน) สำหรับผู้เล่น Y1 ที่มาพร้อมกับระบบปฏิบัติการที่เก่ากว่า 2.0.0
rom_y2.zipY2Android 4.4.2เพิ่ม Wi-Fi, GPS และ FM ให้กับ Bluetooth จากโรงงาน ชิปวิทยุ Y2 เปิดใช้งานโดยสมบูรณ์ ดังนั้น FM ก็ใช้งานได้ที่นี่เช่นกัน

รูปภาพเหล่านี้เป็นฐาน Android ในสต็อก (AOSP) ที่เปิดใช้งานวิทยุไร้สายของอุปกรณ์ ดังนั้นเฟิร์มแวร์ที่กำหนดเองจึงสามารถเพิ่มคุณสมบัติเครือข่ายแทนการเปลี่ยนสแต็กวิทยุ เป็นจุดเริ่มต้นที่เป็นประโยชน์สำหรับขั้นตอนการเผยแพร่ด้านล่าง

ใช้ชื่อเนื้อหาที่เผยแพร่เหล่านี้

ชื่อไฟล์เป็นส่วนหนึ่งของสัญญาณความเข้ากันได้ รักษาชื่อให้ถูกต้องและใส่ไฟล์ ZIP ไว้ในเนื้อหาที่เผยแพร่ของโปรเจ็กต์ ไม่ใช่แค่ในแผนผังแหล่งที่มาของที่เก็บ

ชื่อสินทรัพย์ ZIP เฟิร์มแวร์และอุปกรณ์ที่รองรับ
สินทรัพย์อุปกรณ์ฮาร์ดแวร์ความหมาย
rom.zipY1Type AY1 อุปกรณ์ที่มาพร้อมกับ OS 2.0.0 หรือใหม่กว่า
rom_type_b.zipY1Type BY1 อุปกรณ์ที่มาพร้อมกับระบบปฏิบัติการที่เก่ากว่า 2.0.0
rom_y2.zipY2Y2แพ็คเกจการติดตั้งแบบเต็ม Y2 แยกออกจากสินทรัพย์ Y1
อย่าเปลี่ยนชื่อแพ็คเกจเพื่อให้พอดีกับรุ่นอื่น Y1 และ Y2 ใช้ไฟล์แพลตฟอร์ม MediaTek ที่แตกต่างกันและการกำหนดค่าการกะพริบ เผยแพร่แพ็คเกจสำหรับฮาร์ดแวร์ที่รองรับจริง

การเชื่อมต่อทำงานอย่างไร

Updater CE อ่านรายการเป็นแคตตาล็อก แต่ละ <package> บรรทัดบอกชื่อโปรเจ็กต์ พื้นที่เก็บข้อมูล โมเดล และตัวจัดการ เมื่อผู้ใช้เลือกโปรเจ็กต์นั้น Updater จะตรวจสอบรีลีสที่เผยแพร่ของพื้นที่เก็บข้อมูลและค้นหา rom*.zip สินทรัพย์.

ประจักษ์

ตั้งชื่อโปรเจ็กต์และแมปกับโมเดล Y1 และ Y2 จำเป็นต้องมีบรรทัดแยกกัน แม้ว่าพวกเขาจะแชร์ที่เก็บก็ตาม

เผยแพร่เผยแพร่แล้ว

มีเนื้อหา ZIP ที่สามารถติดตั้งได้ การเผยแพร่ครั้งเดียวอาจมีแพ็กเกจ Y1 Type A, Y1 Type B และ Y2 เข้าด้วยกัน

Updater CE ติดตั้ง

ใช้รุ่นที่เลือกเพื่อเลือกแพ็คเกจที่ตรงกันและเส้นทางการกะพริบเฉพาะรุ่น ผู้ใช้ไม่ควรต้องเดาชื่อไฟล์

เผยแพร่โครงการในห้าขั้นตอน

  1. แยกที่เก็บ Updater CE สร้างทางแยกของคุณเอง y1-community/Innioasis-Updaterจากนั้นโคลนส้อมของคุณภายในเครื่อง
  2. เตรียมพื้นที่เก็บข้อมูลเฟิร์มแวร์สาธารณะ ตรวจสอบให้แน่ใจว่าที่เก็บเป็นแบบสาธารณะและการเผยแพร่มีเนื้อหา ZIP ที่ถูกต้อง คุณสามารถใส่ rom.zip, rom_type_b.zipและ rom_y2.zip ในรุ่นเดียวกันเมื่ออยู่ในเวอร์ชันเดียวกัน
  3. แก้ไขรายการ เปิด slidia_manifest.xml ในรากของทางแยก Updater CE ของคุณ เพิ่มหนึ่งบรรทัดสำหรับแต่ละรุ่นที่รองรับรุ่น (Y1 และ Y2 เป็นคู่ทั่วไป) ที่ repo ค่าเป็นของที่เก็บ owner/repository; url เป็นหน้าโครงการสาธารณะ
  4. ทดสอบแค็ตตาล็อก เรียกใช้ Updater จากการชำระเงินที่แก้ไข เลือก Y1 และยืนยันว่าโครงการแสดงสินทรัพย์ Y1 เลือก Y2 และยืนยันว่าแสดงรุ่น Y2 ตรวจสอบ Type A และ Type B แยกกันเมื่อมีการเผยแพร่ทั้งสองรายการ
  5. เปิดคำขอดึง พุชการเปลี่ยนแปลงรายการไปยังทางแยกของคุณและเปิดคำขอดึงกับที่เก็บอัปสตรีม Updater CE รวมลิงก์โปรเจ็กต์ รุ่นที่รองรับ แท็กการเผยแพร่ ชื่อสินทรัพย์ และอุปกรณ์ที่คุณทดสอบ

สร้างรายการรายการของคุณ

กรอกข้อมูลลงในที่เก็บและทำเครื่องหมายทุกรุ่นที่รีลีสรองรับ เครื่องกำเนิดไฟฟ้าเขียนอันหนึ่ง <package> บรรทัดต่อรุ่นและรวมเฉพาะแอตทริบิวต์ที่คุณกำหนดไว้ ดังนั้นผลลัพธ์จึงตรงกับปัจจุบัน slidia_manifest.xml รูปแบบ การอ่านแอตทริบิวต์ Updater CE ทุกรายการมีให้ด้านล่าง — ตัวเลือกเสริมอยู่ใต้ ตัวเลือกเพิ่มเติม.

พื้นที่เก็บข้อมูลสาธารณะ GitHub เครื่องกำเนิดสารสกัด owner/repository จาก URL
แสดงในแอปและแค็ตตาล็อกไซต์
หน้าพบปะผู้คนสำหรับโปรเจ็กต์หรือบันทึกประจำรุ่น
ล้างข้อมูลนี้เพื่อใช้แบรนด์เริ่มต้นของโมเดล SR1, Q3, Q5 และ Q3e เป็นรุ่น Timmkoo
อุปกรณ์ (แต่ละบรรทัด)
สำหรับรุ่นที่ไม่ได้ระบุไว้ข้างต้น โมเดลที่รู้จักจะเก็บการสะกดแค็ตตาล็อกไว้
ธง

Keep Data จะมีให้เฉพาะเมื่อเฟิร์มแวร์ขาเข้าและเฟิร์มแวร์ที่ติดตั้งเหมือนกันหรือใช้ร่วมกัน derivative ราก. ใช้แฟล็กเฉพาะเมื่อข้อมูลผู้ใช้ไม่สามารถถ่ายโอนได้อย่างแท้จริง

ตัวเลือกเพิ่มเติม: ไอคอน อาร์ตเวิร์ก เนื้อหาที่เผยแพร่ หลังการติดตั้ง และมิเรอร์

ไอคอนและงานศิลปะ

เลือกรูปภาพที่คุณจะส่งไปยังพื้นที่เก็บข้อมูล สิ่งนี้จะแสดงตัวอย่างและสร้าง URL แบบดิบ มันไม่ได้อัพโหลดอะไรเลย
พาธไปยังอิมเมจที่คอมมิต ซึ่งสัมพันธ์กับรูทของที่เก็บ
URL รูปภาพโดยตรง เมื่อว่างเปล่า แอปจะใช้การเผยแพร่ updater.png หรือไอคอนที่สร้างขึ้น

ไอคอนธีมสีเข้มเสริม image_dark เป็นนามแฝงที่ยอมรับ
งานศิลปะรอง ทดลองหลังจากภาพที่วางจำหน่ายและ icon.

ปล่อยสินทรัพย์

ชื่อเดียวสำหรับทุกรุ่นที่เลือก ปล่อยว่างไว้เพื่อใช้ rom.zip บน Y1 และ rom_<model>.zip ที่อื่น
Glob ใช้เมื่อไม่ได้ตั้งชื่อรหัสไปรษณีย์ของรุ่น rom*.zip.
Glob สำหรับแพ็คเกจ Y1 Type A เมื่อชื่อไม่ได้กล่าวไว้
Glob สำหรับแพ็คเกจ Y1 Type B เมื่อชื่อไม่ได้กล่าวไว้

ลิงก์ มิเรอร์ และตระกูล Keep Data

เปิดหลังจากติดตั้งสำเร็จ
ขั้นตอนที่สองที่ไม่บังคับสำหรับคู่มือการตั้งค่าแบบหลายหน้า
คั่นด้วยเครื่องหมายจุลภาค *-mirror ที่เก็บที่สร้างแพ็คเกจ Portable Flashing Zip
เฟิร์มแวร์รุ่นนี้สร้างขึ้นจาก เฟิร์มแวร์ที่เกี่ยวข้องจะแชร์พาร์ติชันข้อมูล ซึ่งเป็นสิ่งที่ Keep Data ตรวจสอบ

ที่เก็บแอปซึ่งมี APK แอปดาวน์โหลดและติดตั้งหลังจากเฟิร์มแวร์

เครื่องกำเนิดไฟฟ้าดึงกระแสออกมา slidia_manifest.xml จากพื้นที่เก็บข้อมูลนี้และแทรกบรรทัดที่คุณสร้างขึ้นไว้ก่อนหน้า </slidia>.


          

        

      


      
บรรทัดเดียวไม่เพียงพอสำหรับพื้นที่เก็บข้อมูลแบบแบ่งใช้ หากบรรทัด Y2 หายไป ผู้ใช้ Y2 จะไม่ได้รับรายการที่ตรงกับโมเดลแม้ว่า rom_y2.zip มีอยู่ในการเปิดตัวโครงการ เช่นเดียวกับรุ่นอื่นๆ ทุกรุ่นที่รุ่นของคุณรองรับ


      
ทุกแอตทริบิวต์ที่รายการอ่าน

      
นี่คือคุณลักษณะที่ Updater CE บิลด์ปัจจุบันเข้าใจ ตัวสร้างจะเขียนเฉพาะสิ่งที่คุณกรอกเท่านั้น แอปจะกลับไปใช้ค่าเริ่มต้นที่สมเหตุสมผลสำหรับส่วนที่เหลือ

      

        

          คุณลักษณะแพ็กเกจ slidia_manifest.xml และความหมาย
          
            
คุณลักษณะจำเป็นมันทำอะไร

          
          
            
nameใช่ชื่อซอฟต์แวร์ที่แสดงในแค็ตตาล็อกและบนการ์ดติดตั้ง

            
repoใช่owner/repo. แอปจะอ่านการเผยแพร่ GitHub ของที่เก็บนั้น

            
deviceใช่โมเดลเป้าหมายตัวพิมพ์ใหญ่ (Y1, Y2, G1, Q3e, …) เก็บหนึ่งรายการต่อรุ่น

            
urlที่แนะนำหน้าโครงการหรือบันทึกประจำรุ่นที่เปิดจากแค็ตตาล็อก

            
type, handlerใช่ในทางปฏิบัติtype="img" และ handler="Custom Firmware". ตัวจัดการประเภทอื่นๆ และตัวจัดการที่ไม่ใช่เฟิร์มแวร์จะถูกข้ามไป

            
brandไม่จำเป็นแคตตาล็อกแบรนด์ (Innioasis, Timmkoo). Empty ใช้แบรนด์เริ่มต้นของโมเดล

            
package_nameไม่จำเป็นปล่อยชื่อไฟล์เนื้อหา ค่าเริ่มต้นเป็น rom.zip บน Y1 และ rom_<model>.zip ในรูปแบบอื่นๆ

            
asset_patternไม่จำเป็นglob ที่ไม่คำนึงถึงตัวพิมพ์เล็กและตัวพิมพ์ใหญ่สำหรับการเผยแพร่ที่ไม่มีชื่อรหัสไปรษณีย์ของเฟิร์มแวร์ rom*.zip (ตัวอย่างเช่น my-firmware-*.zip).

            
type_a_asset, type_b_assetไม่จำเป็นGlobs ที่ระบุ Y1 Type A และ Type B zip เมื่อชื่อไฟล์ไม่มีเครื่องหมายปกติ

            
iconไม่จำเป็นURL โลโก้ ใช้หลังจากออกวางจำหน่ายแล้วนั้นเอง updater.png / updater.jpgและเป็นทางเลือกสำรองสำหรับทุกๆ รุ่น

            
icon_darkไม่จำเป็นโลโก้ธีมสีเข้ม image_dark เป็นนามแฝงที่ยอมรับ

            
imageไม่จำเป็นงานศิลปะแสงรอง ลองใช้แล้ว icon.

            
post_install, post_install2ไม่จำเป็นเปิดเพจหลังจากการติดตั้งสำเร็จ ส่วนที่สองครอบคลุมคำแนะนำแบบหลายขั้นตอน

            
portable_zipsไม่จำเป็นคั่นด้วยเครื่องหมายจุลภาค *-mirror repos ที่เผยแพร่แพ็คเกจพกพาที่พร้อมใช้งาน

            
derivativeไม่จำเป็นพื้นที่เก็บข้อมูลที่เฟิร์มแวร์สร้างขึ้น เฟิร์มแวร์ที่มีรูทอนุพันธ์เดียวกันสามารถเก็บข้อมูลผู้ใช้ได้

            
info_repoไม่จำเป็นพื้นที่เก็บข้อมูลแอปที่มีการเผยแพร่อธิบายถึงสิ่งที่เฟิร์มแวร์ปรับใช้ กำหนดให้มี post_install หรือ post_install2.

            
apk_repoไม่จำเป็นที่เก็บแอปซึ่งมี APK ติดตั้งแอปหลังจากเฟิร์มแวร์

            
min_versionไม่จำเป็นซ่อนรายการเมื่อ Updater CE เก่ากว่าเวอร์ชันนี้

            
do_not_keep_dataไม่จำเป็นtrue (อีกด้วย 1 / yes) บล็อกการเก็บข้อมูลอย่างสมบูรณ์สำหรับเฟิร์มแวร์นี้

            
slugไม่จำเป็นตัวระบุที่เสถียรสำหรับลิงก์และบันทึกการติดตั้งที่บันทึกไว้ สร้างจากชื่อและรุ่นเมื่อว่างเปล่า

            
descriptionไม่จำเป็นคำอธิบายแคตตาล็อกแบบสั้น อาจเป็นค่าแอตทริบิวต์หรือข้อความขององค์ประกอบก็ได้

          
        

      

      
ชื่อดั้งเดิมยังคงอ่านเพื่อความเข้ากันได้: model, package, portable_zip, post_install_2, min_app_version และ image_dark. รายการใหม่ควรใช้ชื่อปัจจุบันด้านบน

  • Y1: ผู้อัพเดตจะเตรียมเส้นทาง Y1 และใช้พาร์ติชั่นที่มีชื่อของอุปกรณ์เมื่อใช้ MTKClient
    • 
        
  • Y2: ผู้อัปเดตจะเตรียมเส้นทาง Y2 และใช้การกำหนดค่า Y2 MT6582 การกู้คืนแบบเต็มสามารถใช้ที่อยู่ทางกายภาพจากข้อมูลกระจายที่ถูกต้องตามแบบจำลอง
    • 
        
  • การสนับสนุนข้ามแพลตฟอร์ม: Updater CE จัดการการแฟลชดั้งเดิมได้โดยตรงบน Windows, Linux และ macOS (รองรับทั้ง Intel และ Apple Silicon Macs) โดยไม่ต้องใช้เครื่องมือการแฟลชเพิ่มเติม
    • 
      

      
ผู้ร่วมให้ข้อมูลควรจัดเตรียมไฟล์เฟิร์มแวร์ที่ถูกต้อง ไม่ใช่ออฟเซ็ตแฟลช อย่าแก้ไขที่อยู่กระจาย ตัวโหลดล่วงหน้า ไฟล์ DA หรือคำสั่งพาร์ติชันเพื่อแก้ไขแพ็คเกจที่ไม่ดี แก้ไขเนื้อหาที่เผยแพร่และทดสอบกับโมเดลที่ต้องการ
